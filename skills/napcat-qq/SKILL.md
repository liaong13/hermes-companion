# NapCat QQ

为 Hermes Companion 的 `hermes-napcat` 插件提供接入、排障、部署和验收流程。NapCat 使用普通 QQ 账号和 OneBot 11；它不是腾讯官方 QQ Bot API 的另一个端点，也不能套用官方 `qqbot` 的 OpenID、沙箱群或回执语义。

完整安装或成套升级优先使用仓库根目录 `INSTALL.md` 与 `python3 scripts/install.py`，不要逐个拼装插件。安装器复用已有配置、检查补丁组合、备份目标并记录真实来源；本 Skill 继续负责安装后的通道排障与场景验收。

## 开始前先分清四层

1. **源码**：开发仓库中的 `plugins/hermes-napcat/`。
2. **安装副本**：当前 `$HERMES_HOME/plugins/hermes-napcat/`。
3. **运行配置与数据**：profile 配置、凭据、社交 home、数据库、NapCat 登录状态；不得进入源码提交。
4. **运行进程**：当前网关实际加载的版本。文件已修改或已安装，不等于进程已重载。

先读取目标仓库和插件文档，再检查当前 profile、安装副本及网关状态。不要用历史机器路径、账号或旧测试结论代替现场证据。

## 权限模型

将以下概念分别处理，不能互相代替：

- **场所准入**：哪些群或私聊可以进入适配器。
- **成员准入**：授权群内哪些成员可以正常聊天。
- **触发条件**：真实 @、正文名称、回复机器人等何时唤醒。
- **身份识别**：QQ 账号和可信事件字段用于区分成员；昵称只用于显示。
- **能力授权**：发送、媒体下载、主机工具、管理动作各自授权。
- **资料可见性**：只读取当前授权群和当前请求明确引用的内容，不因同群关系扩大到私聊、其他群或主人资料。
- **记忆归属**：主人私聊、群公共事实和各成员资料不能混成无范围记忆池。

群内按当前群名片优先、QQ 昵称次之称呼成员；同名不合并，改名不改变账号权限。普通群成员获准社交不等于主人权限。公共群默认不加载私人身份与记忆文件；显式启用 `shared_identity` 后，只使用通道提供的同源 SOUL 和私密侧筛选、独立审核的非敏感日常摘要，保守明确托付的秘密，不直接加载 USER/MEMORY 原文或私人历史。工具定义共用主人 NapCat 私聊基准，但每次执行仍按真实身份、数据来源、副作用和输出场所授权。群工具不得借共享人格读取私人文件、密钥或敏感审批；这类请求须转已验证私聊。

## 配置与连接检查

- 使用 Hermes 支持的配置 CLI，先运行对应 `--help`；不要手工重写 `config.yaml`。
- 凭据只放当前 profile 的 `.env`，不要打印 token，也不要把真实账号、群号或签名 URL写入公开文档。
- 默认让 NapCat WebUI 和 OneBot 监听回环地址；账号登录不等于授权公开管理界面。
- 同一 OneBot 正向 WebSocket 只保留一个事件接收者，避免新旧网关同时接管。
- 检查 `self_id`、主人身份、允许群、成员策略、触发策略和媒体群清单是否分别匹配。群消息准入不自动启用媒体。
- strict 公共群运行时要求插件、宿主合同、worker、策略 revision 和独立社交 home 匹配；任一漂移应失败关闭，不能回落到私人 agent。

## 文本消息排障

按真实链路由外到内检查：

1. NapCat 账号在线，OneBot WebSocket 可访问且认证匹配。
2. 网关日志出现当前启动后的 NapCat 连接成功记录。
3. 指定群／私聊通过场所和成员准入。
4. 当前消息满足配置的触发条件。
5. 事件进入 adapter 队列，模型调用完成且回复能力仍有效。
6. OneBot 返回发送回执；真实验收再从 QQ 客户端确认消息可见。

`reply` 段本身不等于真实 @。若配置允许“回复机器人”唤醒，应通过 `get_msg` 核对引用消息属于同群、确由本账号发送且来源未撤回；回复其他成员或跨群消息不得唤醒。正文名称触发只影响唤醒，不授予身份或权限。

重启窗口内的消息可能存在于 QQ 客户端却未进入网关。只有连接日志时不能宣称已经回复；用新消息完成客户端验收。

## 图片、文件与语音

- 先区分同条消息附件、同群明确引用、上传通知和普通聊天 URL；它们不是同一种授权来源。
- 只在明确启用的群和媒体类型中处理。使用不透明 message/file handle，不以文件名搜索或全群历史作为默认回退。
- URL 下载策略即使允许任意公网 HTTPS，也必须保留 HTTPS、TLS、DNS 公网地址钉定、回环／内网／元数据阻断、禁代理／Cookie／重定向、体积、超时和并发限制。
- 不打印完整签名 URL；诊断只保留必要的 scheme、hostname、port 和脱敏错误类别。
- 图片模型、文件解析器、ASR 是独立能力。模型目录声称支持某模态，不等于当前部署已经完成真实推理验收。
- 撤回、断开和取消必须阻止迟到回复，并回收下载、解析及 worker 子进程；不能只检查任务字典已经清空。
- 媒体请求在接纳时绑定当时可见候选，执行时只复核 TTL、撤回和权限，不能重新选择后来出现的附件。
- 自然接话与明确寻址分别检查真实队列入口：前者须在提前返回前保留可信短期媒体索引和引用来源。先区分只登记媒体存在、纯图主动视觉识别、图文同条及明确短期候选引用；只有已有用户授权和群／媒体／云配置同时允许，纯图才能自动调用视觉模型供本群短期上下文参考，不能把视觉派生直接当作回复或操作确认。纯图识别须异步绑定精确原消息，后续文字不撤销仍有效的图片感知；撤回、暂停、断线、卸载或策略变化则使迟到结果失效。可选接话给识图有限等待，超时仍标注内容未知、不得借旧话题猜图。文字＋附件及明确引用继续复用原媒体链路，不以重新 @ 修复；勿把社交提示／近期 JSON 一起送给视觉模型，正常点名不受牵连。
- 成对验证候选冻结与失效：加入第二候选不应重选；原项移除、过期或撤回仍须拒绝。生成不同逻辑媒体的 fixture 时使用不同不透明 handle，避免按 handle 去重造成伪失败；不把文件名当身份或授权。
- 真实视觉验收使用无敏感合成图、现有模型／登录及正式 worker/FIFO/source codec/AIAgent，分开断言 parser 进程、视觉 HTTP、派生资料进入实际最后 user 与 wire、最终内容、凭据未落盘和 QQ 未测试。观测器须保持任务局部 MediaService 副本的 self，不将识别方法绑定回原实例而绕过其 I/O guards；不能用 fake 视觉或非空回复冒充看懂。

- 自然媒体引用按用户真实说法回归，覆盖指代、常用图像名词与明确请求；先纯图后单独提问，核对前图 origin 与当前 request route，不用同条附图或单一“刚发的图”说法代替跨消息引用验收。自然语言只识别类型，实际来源仍由既有群／作者／TTL／唯一候选绑定，多个或失效候选不猜选。
- 验收按实际问题规定必答内容，不任意强制额外方位或最低字数；实体－属性须配对，主动陈述的方位仍需正确。保留首次失败，区分链路错误与判据误判，修正后实际重跑，不改写模型输出。
- 图片理解若改用当前网关 GPT，按当前 profile 的 `model.default`／`openai-codex` 和宿主 OAuth resolver 解析，不把 CLI 会话临时模型或旧 Qwen-VL 当默认；保留群媒体准入、原图归一化、无回落和单次调用约束。低分辨率图可能把正方形误识为长方形；保留原失败报告，核对真实像素、归一化与合理分辨率后重跑，不能靠放宽图形判据报通过。

## 独立主动社交与迁移

`hermes-napcat 0.3.0` 起只提供可信事件和受限通道能力，参与策略、近期上下文、节流、暂停、空闲机会与公开风格归独立 `hermes-social`；其配套 Skill 是 `hermes-social:social-participation`，不是常驻执行器。`hermes-scoped-memory` 继续拥有记忆归属；只读上下文合同及 worker prepare 不代表长期记忆已经接通。

- 策略位于 `plugins.entries.hermes-social.settings.channels.napcat`，不再由连接器读取旧 `extra.proactive`。自然接话直接共用 `allowed_groups`，不维护第二套群白名单；`targets` 只为显式 idle 目标，不自动跟随群白名单扩大。
- 使用现有 `ctx.register_platform_handler` 和 adapter 的 `_wire_plugin_handlers`，不新开 OneBot 接收者。controller 只持有受限 port，不导入连接器／client／worker／私人 agent。源码与安装分开验证；缺失／禁用／卸载社交插件时仍测试正常点名和主人私聊。
- SDK 接线缓存键是 `(ctx.manifest.name, factory.__qualname__)`。factory 须兼容每次新 port、重复调用、native 重建与重连；卸载同步禁止发言／detach，再取消和 join，只清自己的键。迟到旧 cleanup 不得撤销新 provider。
- 将 transport 活动 revision 与 social generation 分开。候选走真实事件和精确 source ledger；idle 走固定目标、连接／活动代数、期限和本 controller 的单次句柄，不伪造用户或借旧许可。模型后重验，先持久化消费再发送和准确回读，未知回执不重放。通知不写近期对话、不刷新续聊窗口。
- 用户配置只用 CLI；启用使用 `hermes plugins enable <name> --no-allow-tool-override`。读取真实 `plugins.enabled` 集合与 entry settings，不臆测 `entries.<name>.enabled` 是开关；原插件、模型、群白名单和 idle targets 不应被意外改变。
- 不在旧服务仍运行时提前复制一次状态。显式 `settings.migrations.napcat_state_v1` 在新 attach 前采用停机后的最新 counters-only 状态；拒绝另一个 live gateway PID，目标存在不覆盖，无源跳过，源保留。配置迁移、文件安装、状态采用与网关重载分别报告。
- 模拟回归覆盖双群／身份／profile、暂停、撤回、新输入、断线、卸载和重复接线，同时保留正常成功路径。状态故障只暂停可选参与，显式 status 控制仍应给真实故障信息。
- 真实 idle facade 检查不等于完整 gateway；真实模型行为用项目验证脚本走 worker、durable FIFO、source codec 与 AIAgent，只替换 OneBot 捕获端。用显式双插件路径验证安装组合、工具表面、隐私 canary 与凭据未落盘；静默与重新加入分别验收，不拿 fake 完成或旧 QQ 记录代替。
- 多人群聊由通道提供可信发言者、真实 @／核验引用和有界公开观察；模型自行辨别话题与是否参与，不以疑问词、称呼或字面重合猜意图。保留实际出站 reply_to 和对应原消息作为交流证据，其他成员插话不抹掉记录，也不证明新消息属于原话题。所有自动化场景必须重新编写合成文本，使用测试参与者、合成活动和 canary；不复制实际聊天原话、地点、姓名、账号、时间线或真实日志，即使改过部分名称也不作为测试资料。真实 QQ 验收与合成夹具分别报告。

普通好友私聊由 `friend_dm` 单独配置：显式名单，或明确启用的白名单群成员资格，且始终先核验当前 QQ 好友；进入隔离无工具社交模型，不能进入主人私人路径。媒体和主动目标另行配置，不从群成员列表自动生成联系目标。自动加好友与多人长期记忆不随此功能开启。当前组件、配置和回退流程以插件 README 为准。

## 主动通知与备用通道

外部定时器或 CLI 发送消息时使用 Hermes 正式 standalone sender 合同，不借用网关进程内 adapter。对可能“已发送但响应丢失”的错误不自动重试，避免重复消息；成功回执与客户端可见性分开报告。

NapCat 是主要 QQ 通道。Mobile MCP 手机 QQ 可作为明确授权的备用出站路径，但它不是持续在线网关，也不能因 NapCat 故障扩大收件人、内容或资料范围。

## 修改与部署

1. 先确认正常授权路径、失败边界和宿主真实 callable/schema。
2. 在源码做最小修改，同时补成功与越权失败测试；新增宿主钩子时既测函数，也测注册结果。
3. 在源码运行插件完整测试和部署测试，保存各自退出码；聚焦测试通过不等于完整套件通过。
4. 对比源码与安装副本。安装测试可能依赖源码 staging 资源，先区分版本漂移、布局前提和业务缺陷。
5. 安装最终组合后，运行离线 probe／doctor；这仍不代表网关已加载。
6. 重启网关后确认新进程连接，再做真实 QQ 文本、触发、昵称、媒体及隔离验收。
7. 分开报告静态检查、自动化测试、安装落位、运行加载、真实 OneBot 调用和 QQ 客户端确认。

不要从运行中的网关进程树绕过保护去重启自身；若环境阻止重启，请用户在独立终端执行受支持的网关重启命令。

## 最小回归清单

- 主人私聊正常；未授权私聊被拒绝。
- 授权群普通成员按策略触发；独立社交插件开启时，白名单内未点名消息可成为候选，也应允许合理静默。关闭可选参与不影响普通点名。
- 当前群昵称正确显示，但昵称变化不改变权限。
- 回复机器人可按授权触发；回复其他成员和跨群引用不能触发。
- 同群授权图片／文件可处理；跨群、撤回、歧义候选和未启用媒体被拒绝。
- 慢文本或媒体任务不会阻塞撤回／断开控制消息。
- 公共群输入不会读取或泄露私人上下文；工具可见不等于获准执行，敏感数据和审批在读取／展示前转私聊。
- 主动发送只到授权目标，异常回执不重放，连接最终关闭。

## 事实报告

一次测试成功只证明所述版本、配置、账号、群和场景。不要把离线 fixture、模拟 OneBot、网关连接或历史客户端记录互相替代。出现差异时优先读取最新代码、安装副本、配置摘要和当前运行日志，并明确仍未验证的层级。
