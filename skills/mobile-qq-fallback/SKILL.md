# Mobile QQ Fallback

通过 Mobile MCP 操作已经登录 QQ 的手机，作为 NapCat 不可用或不适合时的备用出站通道。它是交互式设备路径，不是持续在线的 QQ 网关，不代表能够后台收信或自动监控消息。

## 使用边界

- 优先使用已配置并可验证回执的 NapCat；只有 NapCat 不可用、不适合或用户明确指定手机路径时才使用本 Skill。
- 发送消息属于外部副作用。必须有当前任务的明确收件人／群和消息内容授权；不得因设备已登录就扩大联系人、群或内容范围。
- 不输入或索取 QQ 密码、短信验证码、支付密码、二次验证代码等秘密。遇到登录、验证、付费或账号安全挑战时停下，请用户在设备上完成。
- 不把昵称当作身份认证。使用 QQ 自身显示的联系人、好友、群号和聊天标题交叉核对。
- 不保存设备 ID、账号、联系人、群号、聊天内容或截图到仓库，也不把一次发送成功描述为长期在线。

## 私聊发送流程

1. 调用设备列表工具，选择工具实际返回且在线的设备；不得从手机型号猜设备标识。
2. 启动 QQ，读取前台应用和当前无障碍元素；若锁屏、未登录或出现认证挑战，停止并说明阻挡。
3. 用对方当前 QQ 昵称或准确 QQ 号搜索。优先选择明确标记为 `联系人`／`我的好友` 的本地结果，排除群、频道、聊天记录命中和同名公共账号。
4. 打开候选会话，核对聊天标题和已有上下文。候选仍不唯一时询问用户，不能猜。
5. 点击输入框并输入文字，但先不发送；刷新元素，核对草稿全文及可用的 `发送` 按钮。
6. 点击 `发送`，再次读取聊天界面；只有在正确聊天标题下看到完全一致的发出气泡，且输入框已清空或发送按钮已禁用时，才报告成功。

## QQ 群发送流程

1. 优先从 QQ 本地会话进入目标群；全局搜索失败不能单独证明群不存在。
2. 首次或目标有歧义时进入 `聊天设置`，以准确 `群号`、当前聊天标题和成员信息共同确认群。返回聊天页后重新读取元素。
3. 按当前群名片／QQ 昵称称呼成员，不用已知真名替代群内显示名。
4. 按与私聊相同的“输入但不发送 → 核对草稿 → 发送 → 回读气泡”流程完成发送。
5. 报告实际观察到的群标题和发出文本；群设置核对与消息回读是两个独立证据。

## 工具使用规则

- 每次导航后刷新前台应用和元素；元素引用只对当前屏幕状态有效。
- 优先点击最新无障碍元素引用。只有控件未暴露时，才依据同一屏幕状态下的新截图使用坐标。
- 仅对不需要检查中间状态的确定步骤使用批处理；搜索结果、权限弹窗、会话选择和发送前草稿必须逐步检查。
- 普通文字发送不需要位置、通讯录等新增权限时，拒绝无关权限并重新检查界面。
- 工具返回成功只证明操作调用完成，不证明 QQ 已发送；必须以界面回读为准。

常用 Mobile MCP 工具顺序：

```text
mobile_list_available_devices
mobile_launch_app
mobile_get_foreground_app
mobile_list_elements_on_screen
mobile_click_on_screen_at_coordinates / mobile_type_keys
mobile_list_elements_on_screen
```

实际工具名称可能带 Hermes 的 MCP 前缀；以当前会话发现的工具为准。
