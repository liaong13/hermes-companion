# 安装修复与统一接入验收

日期：2026-10-31；源码起点 `历史修订`。本页记录安装排查后的修复、统一安装入口及其验证范围。此前功能开发文档中的“未安装”“待重启”和测试数量属于各自阶段，不作为当前状态。

## 三类安装问题与修复

| 问题 | 是否可能影响其他安装 | 当前处理 |
| --- | --- | --- |
| scoped-memory 顶层依赖 `yaml`，Hermes PM 选中的环境没有 PyYAML 时导入失败 | 会，取决于实际运行环境；旧 venv 有依赖不能证明网关环境也有 | provider 与个人命令改用宿主 `hermes_yaml.safe_load`；子进程阻断 PyYAML 后验证真实导入和命令 |
| 旧安装来源仍指向独立 NapCat 仓库，单独升级容易遗漏匹配的 worker、数据层或补丁 | 会，旧来源记录或手动复制可能造成版本混用 | 统一分发四个完整插件目录，按实际 Git origin、子目录及 revision 写来源，另外记录文件哈希；暂存清单补齐 `social_memory.py`、`pyproject.toml`，包版本与清单一致 |
| social 后台只记录异常类型，strict 启动通知没有当前回复许可，宿主文本 fallback 可能重复发送 | 会，取决于端口组合、通知配置及发送结果 | 附着前校验关键端口签名；日志只记代码位置；安装配置关闭启动通知；拒绝或未知送达不进行文本重发，并保留安全拒绝码 |

历史 `AttributeError` 缺少调用栈，无法反推出唯一根因。本轮修复可复现的端口不匹配与诊断缺口；不能将其写成已证明历史异常的具体原因。历史某次发送失败也不足以区分许可失效和传输失败。

## 当前配套与接入范围

| 组件 | 清单版本／合同 | 成套接入中的用途 |
| --- | --- | --- |
| `hermes-napcat` | `0.5.0`；runtime contract 5、worker host contract 4 | QQ 通道、可信来源、公共群工具回合和唯一出站 |
| `hermes-social` | `0.2.0` | 自然参与、统一额度、近期上下文与 bundled Skill |
| `hermes-life-memory` | `0.3.0`；social-memory contract 1 | 本人核对的人物候选，可选本地交流、经历及约定 |
| `hermes-scoped-memory` | `0.3.1`；公共 API 1 | 完整兄弟数据层与 prepare worker；不自动激活 provider |
| Hermes 宿主 | 补丁基线 `5894e750c3dba980d43b25aa29e3958149ba2c61` | 公共群、公开风格、安静交付增量；本地交流另加上下文增量 |

同一版本号还需结合 revision、文件哈希和实际宿主补丁核对。memory-provider 的 `llm-facade.patch` 属于另一条实验接线，不是本地规则记忆的安装前提。

完整操作见 [INSTALL.md](../INSTALL.md)，agent 入口为 [仓库 AGENTS](../AGENTS.md)与 [安装 Skill](../skills/hermes-companion-setup/SKILL.md)。当前支持 Linux、可修改的兼容 Hermes 源码、bubblewrap 与已有 NapCat。不会代登录账号、部署 NapCat 容器、选择付费模型或安装全部外部服务。

首次基本安装配置自然接话与显式人物候选；组件独立使用的默认配置仍为关闭。普通对话采集、规则候选、共同经历与约定需选择 `--features local-memory`；原群主动约定联系另需 `--proactive-agreements` 和明确的 `--idle-groups`。升级保留既有停用选择、记忆群和参与范围，扩大聊天白名单不扩大采集。私人 memory provider 保留。

终检补充覆盖全局 `plugins.disabled`：旧 life-memory/social 的全局停用会映射为对应功能关闭，显式 `--features`／`--enable-social` 才恢复。该升级回归先复现失败，修复后与安装器全套一起复验；其他插件的停用清单保留。

安装器默认只输出计划；`--apply` 才写入，`--restart` 才请求正式激活。配置使用 Hermes CLI，依赖交给 Hermes PM；不同于 PM 所选解释器的旧 venv 不作为默认。来源、哈希和激活记录写入目标 home 的 `companion-install.json`，精确备份保存在 `backups/hermes-companion/`。并发修改会被保留并报告，激活失败保留已验证的安装，返回 `restart_required`。

## 已执行的验证

复现变量与组件命令见[开发基线](可移植性与开发基线.md)；安装器夹具命令见 [INSTALL.md](../INSTALL.md#仓库内的安装验证)。宿主使用上述源码基线及已有增量；安装器、social 和 NapCat 使用 PM 选中的 Python 3.14.9 环境，scoped-memory pytest 套件使用已有 Python 3.11.15 测试环境。未为测试向系统或活动 PM 环境安装依赖。

| 范围 | 结果 | 证据边界 |
| --- | --- | --- |
| 统一安装器 | 19 项通过，无跳过 | 含真实基线补丁组合、一次性 home 的配置 CLI／解析器／bubblewrap worker、重复安装；PM 下载与 gateway 激活由夹具替代 |
| scoped-memory 完整套件 | 225 passed、2 skipped | Mem0 插件源码显式提供、后端离线；两项 skip 需要单独的 `llm-facade.patch`；保留 809 条既有弃用告警 |
| social 完整套件 | 107 项通过 | 包含旧端口拒绝及日志隐私回归；无真实 QQ 或云端模型 |
| NapCat 定向回归 | 47 项通过 | `test_plugin` 与 `test_isolation`，含未知送达不重发、strict 拒绝码和暂存；不是本轮重跑全部媒体套件 |
| 正式群回合 | 1 项通过 | 真实 GatewayRunner、持久 FIFO、source codec、AIAgent 与回环模型服务，OneBot 为捕获端，不连接 QQ |
| 已安装副本定向复验 | social 107 项、NapCat 14 项、无 PyYAML 导入 1 项通过 | 使用新选定的 PM 环境；源码目录专用的暂存测试不作为活动安装目录测试 |
| 静态检查 | 可移植性扫描、Python AST／TOML、Markdown 本地链接、mode／LF 和 `git diff --check` 通过 | 不读取或分发凭据、个人资料与运行数据库 |

安装副本第一次运行整份 `test_plugin` 时，暂存夹具因目标位于受保护 `plugins` 路径而报错；源码树中的对应回归通过，未放宽生产路径拒绝。最初的安装器集成夹具也曾因未准备 PM 依赖选择失败，修正一次性夹具后完成上表验证；没有以这些中间失败宣称通过。

最终复验确认活动 PM 环境没有 pytest，因此 scoped-memory 全套沿用已准备的测试解释器；这不阻止该环境实际导入 provider，导入及个人命令由独立子进程回归验证。没有为了运行测试给活动环境补装依赖。

## 运行状态与未验收项

本轮已在获准运行环境修复导入、来源记录与启动通知配置，通过正式 CLI 重载并观察 NapCat connected、life-memory/social 附着。私人 Mem0 选择保留；普通对话采集、经历和约定未在该环境开启，缺少本地上下文宿主合同时不启用相关功能。公开文档不保存该环境的路径、账号、群号、PID、凭据或聊天正文。

新的统一安装器仅在合成 home 完成安装与重复安装验证，对真实 profile 只做只读计划；不能把此前人工修复的运行加载当作新安装器的真实部署验收。未发送本轮 QQ 测试消息，未验收真实客户端送达、本地交流／约定闭环、真实 embedding／Whisper 或任意 Hermes 版本兼容。后续在用户授权的目标中分别验收连接、消息行为和可选功能。
