# 话题参与：研究依据与实现

日期：2026-10-31。本次落实社交优先级中的 P0 与连续接话切片：先判断话题、回应对象及参与机会，再经原通道回复。源码改动不代表已经安装、重载或通过真实 QQ 验收。

## 原问题与新行为

原控制器会在合并后的可参与文本中主要选择最新一条。此前的分享、请求即使仍在公开上下文里，也失去了独立选择机会。纯文本指向其他成员时，则仅靠最终生成模型决定是否沉默。

现在每次有界合并后增加一次无工具的公开模型判断。所有合格候选一同送入，不按问号、疑问词、短答词表或兴趣关键词预判语义。每条候选返回：

- 面向对象：自己、全群、其他成员或不确定。
- 行动：回应、观察或等待。
- 话题锚点：捕获资料中该候选自身或更早的真实消息。
- 原因码：提问、分享、续接、纠正、玩笑、结束、对别人说话、不清楚或无新贡献。

整个批次最多选择一条；允许全部不参与。面向其他成员、对象不清和结束等结果不能被选为回应。选择较早的分享时，继续派发该分享的原始 event/source，不把它伪装成最新发言者的请求。

话题关联只保存为短期模型假设，不写入人物事实或长期关系。当前属于批次内关联加真实交流证据，尚不是跨会话的完整多人话题图。相同发言者不会自动被归入同一个话题；同名成员由本轮临时别名区分，昵称只帮助理解语义。

连续交流继续依据真实出站 reply-to 找到原请求／回复对。选择阶段会保留当前候选对应的实际来回，即使其他成员的消息把它推到最近十二条以外。生成快照优先保留话题锚点与这对交流证据；必要时裁剪展示片段并标记，不改用户原文。已核验引用给其他成员的历史消息也标为背景。

## 范围、预算与失效

实现入口为 [participation.py](../plugins/hermes-social/participation.py) 与 [controller.py](../plugins/hermes-social/controller.py)。现有配置键、群白名单、ParticipationPort 和公共上下文合同版本保持一致；升级源码后，已启用的自然接话会使用新判断阶段。

- 每批最多十六个候选；单条原文超过 11500 UTF-8 bytes 不进入可选判断。选择输入 JSON 最多 24000 bytes，先淘汰背景，仍超限则放弃该批次，不隐瞒候选尾部后猜测意图。
- 每批增加至多一次宿主 `ctx.llm` 调用，`max_tokens=2048`、请求 timeout 为十五秒、整个等待最多二十秒。选择后生成回复仍走原正式 gateway 路径，模型和网络开销因此增加。
- 模型只取得当前群公开资料及可选公开自述；使用空 Context 和当前 profile，不加载私人 SOUL、USER、MEMORY、CLI 历史或其他群资料，不提供工具。
- 模型响应严格核对字段、候选完整性、对象／行动一致性和话题时间顺序。未绑定引用、畸形结果、超时和服务错误均保持安静，不退回“选择最新消息”。
- 判断期间最多容忍八条普通新活动；明确请求、暂停、撤回、忘记、自己已发出的回复、卸载或连接代数变化使旧判断失效。忘记已经淘汰的来源仍能撤销依赖它的判断和可选许可；无关的重复通知不撤销新交流。
- 可选媒体继续使用更严格的新活动失效规则。通道拒绝某个选择后不重试原 source，控制器仍能处理判断期间新到达的下一批消息。
- 短期选择视图最多一百八十秒，且不超过依赖记录原有的十分钟有效期。最终发送许可仍由通道针对原 source 核发，模型不能扩大权限或改目标。

日志只增加行动／对象／原因码和选择次数，不记录消息正文或模型内部推理。模型可以误判语义，确定性检查只能保证它未越出给定合同，不能保证自然交流质量。

## 验证与复现

组件回归在社交插件目录运行：

```sh
TMPDIR=/tmp HERMES_DISABLE_LAZY_INSTALLS=1 PYTHONDONTWRITEBYTECODE=1 \
  hermes --run-module unittest discover -s tests -p 'test_*.py'
```

新增专项测试使用独立构造的合成身份和消息，检查较早分享选择、纯文本对象判断结果的执行、交错短答、同名、其他群隔离、错误输出、原 source 绑定及撤回／忘记／暂停／连接变化竞争。假模型验证的是合同和执行机制，不是自然语言理解效果。

真实模型的三组合成语义探针复用现有入口：

```sh
TMPDIR=/tmp python3 integration/hermes-host/verify_social_idle_live.py \
  --live --participation --host "$HERMES_SOURCE" --owner-home "$HERMES_HOME" \
  --social-plugin-root "$COMPANION_SOURCE/plugins/hermes-social"
```

该探针仅经正式 PluginLlm 调用既有模型；不创建 controller、adapter 或发送能力。报告记录候选选择、话题关联、耗时及 token 数，不能替代正式 worker／FIFO／source codec／gateway 捕获链路或真实 QQ 验收。

本轮已完成：社交插件 143 项离线测试；三组合成语义探针全部通过，实际宿主模型为 `openai-codex / gpt-6-luna`，三次耗时分别为 3.681、2.585、4.566 秒，共报告 2131 tokens。这是本次小样本，不作为稳定延迟、费用或准确率承诺。

正式捕获链路的十个合成场景全部通过，覆盖原 worker、durable FIFO、source codec、AIAgent、原目标发送及回读；OneBot 连接尝试为零，凭据落盘扫描无发现。两项负例保持沉默，其余八项各有一次已捕获回复；其中包含纯文本交给其他成员、十四条插话后的短答，以及分享后紧跟“哈哈”的批次。该探针只在合成 profile 中为真实模型传输注入官方只读解析的内存凭据，不修改使用者的登录文件。场景相较历史版本有扩充，不能将十项通过当作与旧九项的严格 A/B 实验。

安装器与可移植性工具测试为 23 项，2 项因缺少测试前提跳过，其余通过。完整 NapCat 回归为 356 项，16 项因宿主／worker 测试前提不满足跳过，其余通过；其中媒体 45 项、生命周期 24 项还分别定向复验通过。旧用例已区分新增的选择调用与最终回复／idle 调用，保留原媒体绑定、原目标和迟到工具撤权断言。完整套件仍观察到既有临时日志 handler 的路径失效错误，不称为零告警。
