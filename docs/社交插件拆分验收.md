# 社交插件拆分验收

## 范围与交付

本轮将原内嵌主动参与拆分为 `hermes-napcat 0.3.0` 的通道能力端口与 `hermes-social 0.1.0` 的运行策略，附带 `hermes-social:social-participation` Skill。实现、配置及回退说明见[拆分合同](社交插件拆分.md)、[社交插件 README](../plugins/hermes-social/README.md)和[NapCat 迁移说明](../plugins/hermes-napcat/docs/主动聊天.md)。

通道保留唯一群白名单、真实身份、worker、精确 source ledger 与最终受限发送；社交插件负责参与、合并、节流、暂停、近期上下文与公开风格。旧连接器 `proactive.py` 和 `social_prompts.py` 已退役，不保留跨插件重导出。没有增加宿主接口、工具、OneBot 连接或模型登录。

`hermes-scoped-memory` 仍拥有记忆归属；当前只读 ContextProvider 默认只接近期真实观察，不代表长期记忆生产接线已完成。加好友、非主人私聊及其他通道实现不在本轮范围。

## 发现与修正

- 迁移回归曾发现 native 重建时第二个 controller 被安装拒绝。工厂改为按 adapter 的弱引用记录已附着实例，控制器只持有 port；最终重复接线、后加载、卸载、再启用和重连回归已通过。
- 社交状态按 profile／platform 分目录，避免未来通道复用同一 controller 时互相覆盖计数；当前实际只接通 NapCat。
- 状态故障不会吞掉显式 status 控制；普通点名与主人私聊继续走原通道。
- 部署后的首次本地核验误用了 `entry.enabled`。实际官方 CLI 使用 `plugins.enabled` 列表；已按真实数据读回验证原集合仅新增社交插件，未扩大工具覆盖权限。错误未被当成成功结果，亦未再次执行整套部署。

完整 NapCat 套件的断言通过，但输出伴随测试临时 profile 删除后的日志 `FileNotFoundError` 和 SQLite `ResourceWarning`。这不是“干净无警告”的测试运行；完整原始日志另存于维护环境，不以过滤输出或通过计数冒充已修复这些夹具回收问题。

配套 Skill 的 SkillSpector `--no-llm` 静态扫描为 LOW／0 findings，文件覆盖率 100%，但 `analysis_completeness=partial`、建议 CAUTION；未执行语义分析，不能当作完整安全认证。
