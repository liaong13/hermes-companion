# Hermes Companion 项目规划

Hermes Companion 的定位已经从“集中存放几个 Hermes 插件”调整为“围绕 Hermes Agent 组合伙伴能力的开放集成项目”。仓库可以容纳插件、宿主集成、部署工具、可复用 Skills、人格模板和经过验证的方案包，但不会把这些不同层次伪装成一个万能插件。

本文记录当前方向与交付边界。它不是发布日期承诺；实际状态以源码、组件状态页和可复现验证为准。

## 愿景与原则

项目希望让使用者建立能够持续活动的 Hermes 伙伴：在授权范围内探索互联网、阅读与创作、参与交流、形成自己的经历，并根据经历修正认识和之后的选择。社交与相关记忆是先完成的基础；通用方案不绑定维护者的名字、关系、账号、记忆或人格。

实例可以提供初始自我描述，但框架不预填任何具体角色；兴趣、经历、认识及表达偏好需要可追溯的修订机制。完整技术路线、验收阶段与现有能力差距见[互联网生活能力开发方案](互联网生活能力开发方案.md)；斯坦福小镇、Agentopia 与 Anuttacon 公开资料的取舍见[研究与代码参考](研究与代码参考.md)。

长期探索包括更可靠的记忆、学习、感知和授权内自主行动，但这些是发展方向，不是当前 AGI 能力认证。项目坚持：

- 身份与表达、事实与记忆、工具能力与权限分别建模，不能相互冒充。
- 人格是可替换内容，不是认证、授权或数据可见性的依据。
- 记忆须保留主体、来源、范围和必要时间；故事、转述、推断、计划与真实执行分开。
- 学习以之后的判断和行动改善为证，不以增加提示词或写入一条记忆宣称完成。
- 已授权功能的可用性与安全边界共同构成正确性；不把“不知道”直接实现成“拒绝一切”。
- 自动化测试、安装、运行加载、集成验证和真实客户端验收分别报告。

## 项目分层

### 1. 通道与设备接入

负责可靠接收外部事件、建立可信身份和回复目标，例如当前的 `hermes-napcat`。通道层可以编排附件，但不应绑定某个人格或具体记忆后端，也不应仅凭昵称授予权限。

未来可接入其他消息平台、设备或 MCP 服务。第三方 MCP 保持独立安装和授权，本仓库可以记录已验证的接法、适用范围和风险，不复制维护者的凭据或私有设备信息。

### 2. 感知与内容处理

处理图片、文件、语音和其他明确授权的输入。感知结果是模型或解析器的输出，不自动成为已认证事实；引用、附件来源、出站模型和解析沙箱分别控制。

当前图片及部分文件场景已有实现和具体客户端记录，语音仍未完成真实 Whisper 全链路验收。

互联网生活运行层沿用插件 ID `hermes-social`，目前先实现交流与约定联系能力；后续统一组织关注事项、活动、经历与复盘，社交只是其中一类活动。首个端口由 NapCat 提供可信事件、白名单、精确来源许可和受限发送；运行层不持有 OneBot 连接或原始私人 agent，其他通道及通用活动执行器尚未实现。见[拆分合同](社交插件拆分.md)。

### 3. 记忆与学习闭环

`hermes-scoped-memory` 研究按用户和来源分域的本地记忆、证据、持久作业、公共事实与混合检索。完整多人生产链路仍受宿主接线、真实模型、删除恢复和部署验收约束。

独立 `hermes-life-memory` 已开始人物层的显式自述切片，复用存储核心，不替换 default 的 Mem0；可信成员原始命令经本人核对后，仅在当前群回应本人时提供临时资料。当前仍是源码与离线验证阶段，见[实现记录](人物记忆首个切片.md)。

后续已补[纯本地记忆与交流续接](纯本地记忆与交流续接.md)：以公共 API 复用数据层，规则生成候选，维护当前成员的同群话题和真实交流，沿来源撤销派生内容。记忆计算不调用 API；匹配宿主提供旧上下文失效与重建，真实部署仍待验收。

学习流程应形成“证据 → 判断 → 执行 → 验证 → 提炼适用条件 → 后续复用与复核”的闭环。可复用任务经验优先沉淀为 Skill；个人事实、群公共事实和项目经验不能混入同一无范围记忆池。

### 4. 持续活动与生活状态

后续生活组件负责关注事项、活动选择、进度、经历证据与反思。浏览、阅读、创作和联系都要有真实输入、执行结果、资源预算和可恢复状态；模拟经历、计划与真实完成分别记录。

优先复用 Hermes 已有 Cron、goal、heartbeat、loops、插件与工具执行，不另造通用调度器。单次活动有完成条件，“持续生活”不能作为无限模型循环。生活组件与社交、记忆分开，通过受限端口协作，完整能力尚未实现。

### 5. Skills 与工具集成

Skills 保存任务流程、工具契约和可复用经验。后续仓库只收录来源、许可证和适用范围明确，且经过必要审查的自有或可再分发内容；第三方 Skill 的安装清单与本仓库发行内容分开。

供应链检查可以结合 Hermes 自带审计与 NVIDIA SkillSpector 等独立扫描器，但扫描结论只是审查证据，不是运行时强制隔离，也不能以低风险评分替代人工复核。

### 6. Personas 与身份模板

`personas/` 是未来的可选分发层，支持任意合法人格或交流模板，不指定默认人物。模板只定义适用的表达和价值取舍，不虚构用户与人格的共同经历，不把用户愿景改写成模板自主产生的愿望。

NapCat 历史合同 4 公共单次问答仍含固定文案。合同 5 的参与与公开风格已从通道移入 `hermes-social`；这不等于可分发 Personas 已完成，公共路径仍不能读取私人 SOUL、USER、MEMORY 或历史。

### 7. 方案包与安装验证

未来的方案包用于把一组已存在的组件、版本约束、脱敏配置模板和验收步骤组合起来，例如“QQ 公共群问答”或“本地分域记忆试验”。方案包不是复制整个 profile，也不自动继承维护者权限。

已提供首个 [Linux 成套安装入口](../INSTALL.md)：覆盖匹配的 QQ／social／本地记忆组件、宿主增量、Skills、配置、精确备份、失败恢复与分层检查。它要求已有兼容 Hermes 和 NapCat，不代登录账号，不把通道白名单自动变成原文采集授权；其他平台、人格和外部 MCP 方案仍按组件推进。

## 实施阶段

### 阶段 A：整理可信基线

- 完成根 README、文档导航和各组件 README 的定位重写。
- 明确源码、安装副本、运行数据、维护环境清单与历史记录的区别。
- 清理源码、测试及文档中的私人绝对路径、个人身份默认值和过时项目名；历史材料同样脱敏，并保留时间、结果与验证边界。
- 给每项能力标注实现、测试、安装、运行和真实使用层级。

### 阶段 B：组件通用化

- 将 NapCat 的固定 persona 从通道源码抽离为显式可选配置。
- 稳定通道、媒体、隔离 worker 和记忆服务之间的最小合同，避免消息适配器依赖具体向量实现。
- 为受支持的 Hermes 版本建立兼容矩阵与自动化检查，不把单一宿主补丁基线当成普遍兼容。

### 阶段 C：社交与分层本地记忆

- 先完成话题／回应对象状态、人物自述核对、场所内召回、忘记与撤回。
- 把自己的交谈经历、共同事件与约定纳入记忆，区分 subject、陈述者、来源和可见范围。
- 在统一联系预算下完成一种有来源的主动分享与反馈退让，保持通道唯一发送者。
- 不改变私人 default 的 Mem0；源码、安装副本与真实运行分别验收。

### 阶段 D：一种真实互联网活动

- 用获准公开来源的阅读／笔记作为首个生活活动，有范围、下一步、完成证据与停止条件。
- 接入持久唤醒、进度与重启恢复；无变化时不消耗模型，不凭叙述认定完成。
- 从真实结果形成自身经历、带证据反思与可复用方法，再扩展第二类活动。
- 语音、视觉和虚拟世界可在后续独立验证，不作为人物记忆与持续活动成立的替代。

### 阶段 E：可分发 Skills、Personas 与 MCP 指南

- 建立目录、清单、许可证、来源和版本约定后再加入真实内容，不预建大量空目录。
- 第三方内容优先链接原项目和安装流程；只有许可证允许且维护收益明确时才镜像。
- 每个 MCP 指南说明服务端、客户端配置、工具范围、凭据、遥测、费用、撤权与真实连通验证。
- 每个 persona 说明它改变什么、不改变什么，以及与记忆和权限的隔离关系。

### 阶段 F：方案包与安装器

- 先提供可人工审阅的方案清单、配置模板、版本锁定和验收脚本。
- Linux QQ／social／本地记忆安装器已实现 dry-run、备份、最小写入、失败回滚及读回验证；继续扩展其他方案，不打包私人 profile。
- 发布前至少覆盖全新安装、升级、卸载／回滚、组件缺失、网络失败和权限不足。

## 不纳入仓库的内容

- 密钥、Cookie、QQ 登录数据、聊天记录、私人记忆库和真实 profile。
- 维护者的 SOUL、关系资料、个人白名单和设备标识。
- 未经许可复制的第三方 Skill、persona、模型或 AGPL 代码。
- 只在本机成立却被写成通用默认值的路径、账号和服务地址。
- 没有执行记录的测试数字、模型效果、费用或“已上线”声明。

## 变更与发布规则

2026-10-31 的源码可移植性整理及后续开发顺序，分别见[开发基线](可移植性与开发基线.md)与[下一步开发评估](下一步开发评估.md)。已补首个成套安装入口以减少人工组合错误；Personas、跨平台方案和阶段 D 的实际生活活动继续独立推进。开始开发前的安装快照见[本地能力核对](本地Hermes能力核对.md)，后续修复、运行加载及新安装器的验证范围见[安装验收记录](安装修复与统一接入验收.md)。

规划变化先更新本文和入口文档，再按组件建立实现任务；规划文本不自动授权修改生产环境。新增组件必须有清单、README、许可证、测试和脱敏示例，外部状态写入须读回准确目标核实。

发布时按组件标记版本，并说明兼容宿主、迁移步骤、回滚方式和验证层级。若当前实现与规划冲突，以实际代码与最新验证为事实，同时把差距列为待办，而不是修改文档掩盖差距。
