# 可移植性与开发基线

测试资料及历史清理要求见[隐私与合成测试资料](隐私与合成测试资料.md)。当前树扫描与历史扫描分别执行，不用当前文件无命中推断旧版本已经清理。

Hermes Companion 的源码可放在任意目录。源码、Hermes 宿主、已安装插件与运行数据分别管理；测试和文档不依赖维护者的用户名、个人记忆主体或私有备份。

## 路径与身份配置

| 变量／配置 | 用途 | 约束 |
| --- | --- | --- |
| `COMPANION_SOURCE` | 本仓库源码根目录 | 文档命令的定位变量；插件不通过它寻找运行数据 |
| `HERMES_SOURCE` | 待验证的 Hermes 源码 | NapCat 测试显式设置时检查 `gateway` 包；未设置则使用当前 Python 的可导入宿主，不猜个人目录 |
| `HERMES_PYTHON` | 已具备所需依赖的 Python 解释器 | 文档和宿主验证工具使用；不假设宿主一定有名为 `venv` 的目录 |
| `HERMES_LAUNCHER` | 安装器集成夹具使用的实际 Hermes launcher | 与 `HERMES_SOURCE`、`HERMES_PYTHON` 配套；缺省则该项明确 skip，不向系统 Python 补装依赖 |
| `TMPDIR` | 存在、可写且允许用于测试的临时目录 | 测试 home 与普通临时数据使用它；媒体预算夹具仍按生产策略放在不含 `.hermes` 的源码目录中 |
| `MEM0_PLUGIN_SOURCE` | 已审阅的 Mem0 扁平 Python 插件源码 | 仅供离线委托集成；缺省明确 skip，显式无效路径失败；只复制源码、清单和 LICENSE |
| `HERMES_HOME` | 实际目标 profile 的运行数据目录 | 离线测试自己创建合成 home；不要将运行 profile 导出到源码树 |
| `owner_mem0_user_id` | composite 模式的主人 Mem0 主体 | 必须显式配置非空字符串，与目标 `mem0.json.user_id` 完全一致；local-only 禁止该字段 |

环境示例只说明变量关系，所有 `/path/to/...` 都须替换为自己的实际位置。先准备依赖，再运行测试：

```sh
export COMPANION_SOURCE="/path/to/hermes-companion"
export HERMES_SOURCE="/path/to/hermes-agent"
export HERMES_PYTHON="/path/to/prepared/python"
export TMPDIR="/path/to/reviewed/writable/scratch"
export HERMES_DISABLE_LAZY_INSTALLS=1
export PYTHONDONTWRITEBYTECODE=1
cd "$COMPANION_SOURCE"
```

`HERMES_DISABLE_LAZY_INSTALLS` 是本次核对宿主支持的开关，避免测试导入 AIAgent 时自动同步依赖或切换解释器；NapCat 测试入口也会设置它。其他宿主版本仍需核对其启动行为。不要把生产 launcher 的成功启动等同于已准备测试依赖。

## composite 配置升级

旧配置如果省略 `owner_mem0_user_id`，新源码会拒绝初始化。升级前由操作者在本地核对原有 Mem0 主体，显式填写同一值，然后对目标 home 运行只读预检并重建 agent。该过程不创建新主体，不改写现有云记忆，也不要求关闭私人 default 的正常记忆功能。

local-only 继续使用独立社交域，不读取主人 Mem0。个人身份不能从用户名、昵称、环境中的请求字段或工具参数推断。各请求仍使用宿主可信身份，配置变化后拒绝沿用旧 agent。

## 公开材料与系统路径

- 代码从自身 `__file__`、宿主 API 或显式配置解析路径；不以维护者机器上的目录作 fallback。
- 测试使用合成身份、数据和凭据。外部插件源码需显式提供，不自动读取任何人的安装目录。
- 文档使用仓库相对链接、变量或 `/path/to/...` 占位。历史材料同样去掉个人绝对路径和主体标识，保留日期、测试数量、失败与验证范围，并说明脱敏。
- GitHub 仓库地址与来源署名保留真实地址，不能为了隐藏本地用户名而破坏公开链接。
- `/usr/bin`、`/proc`、`/work/home` 等系统／沙箱路径，以及负向测试中的合成路径有各自契约；清理个人目录不等于替换所有绝对路径。
- `integration/hermes-host/test_llm_patch.py` 目前仍使用系统 `/tmp`，仅在一次性宿主副本中把 runner 的 `/var/tmp` scratch 改为 `/tmp`；这是已知工具限制，详见其 [README](../integration/hermes-host/README.md)。

静态检查运行：

```sh
python3 scripts/check_portability.py
git diff --check
```

检查脚本覆盖 Git 跟踪文件及未忽略的新文件，报告个人 home 绝对路径、旧项目名和需另行审查的符号链接。它不扫描 `.git` 历史、被忽略的运行数据或二进制内容，也不承担完整密钥扫描。当前源码脱敏不会改写过去的提交。

## 离线复验

```sh
PYTHONPATH="$HERMES_SOURCE" "$HERMES_PYTHON" -m unittest discover -s plugins/hermes-napcat/tests
PYTHONPATH="$HERMES_SOURCE" "$HERMES_PYTHON" -m unittest discover -s plugins/hermes-social/tests
"$HERMES_PYTHON" -m unittest discover -s plugins/hermes-napcat/deploy -p 'test_*.py'
"$HERMES_PYTHON" -m unittest discover -s skills/moviepilot-torrents/tests
# 需要真实 Mem0 插件类的离线委托测试时，额外设置此变量
export MEM0_PLUGIN_SOURCE="/path/to/reviewed/mem0-source"
PYTHONPATH="$HERMES_SOURCE" "$HERMES_PYTHON" -m pytest -q -rs -p no:cacheprovider plugins/hermes-scoped-memory/tests
```

这些命令只应使用已准备好的解释器。测试会启动合成本地 HTTP／WebSocket 服务或沙箱进程，不连接 QQ，也不据此证明真实模型质量、云端政策或生产加载。

## 2026-10-31 安装修复后的开发验证

完整接入优先使用 [INSTALL.md](../INSTALL.md)，安装器自行解析 launcher 和 PM 选中的解释器。开发测试仍用显式变量；需要运行安装器的两项真实宿主夹具时，在已准备环境中执行：

```sh
export HERMES_LAUNCHER="/path/to/actual/hermes"
HERMES_DISABLE_LAZY_INSTALLS=1 PYTHONDONTWRITEBYTECODE=1 \
  HERMES_SOURCE="$HERMES_SOURCE" HERMES_PYTHON="$HERMES_PYTHON" \
  HERMES_LAUNCHER="$HERMES_LAUNCHER" \
  python3 -m unittest discover -s tests -v
```
