# 多人请求编排、跨天记忆与方法学习

本阶段落实路线图 1、2、3、5：每人独立请求、群回复编排、跨天明确记忆、可验证且可撤销的方法学习。第 4 项自主研究／阅读不扩展，已有阅读与联系范围继续按原配置运行。版本为 social `0.5.0`、NapCat `0.7.0`、life-memory `0.4.0`、scoped-memory `0.3.2`。

## 每个人的请求与条件

`requests.py` 将宽泛话题与个人事项分开。一个话题内 A、B 可以分别提出请求；原始消息 ID 是请求根，实际 QQ 身份决定请求人，昵称和模型输出不能改写身份。

条件保留实际提供者。B 补充某信息并不自动成为 A 的条件；A 明确采用后，账本同时记录提供者 B 和采用者 A。纠正保留替代关系，有歧义则澄清，不能把同主题、相近时间或回复顺序当作采用证据。一个人的撤回不删除另一人的独立请求。

请求状态包含 `pending`、`waiting`、`deferred`、`responded`、`closed`、`cancelled`。持久化内容限身份、来源、条件关系、状态与期限元数据，不保存聊天正文。重启后的上下文仅按已知消息 ID、原作者和原时间进行至多 8 次精确回读；旧话题不是新入站或新发送许可。

自然接话与获准好友使用独立的真实观测凭据，精确绑定实际事件、来源、当前范围、连接及原期限；它不授予发送或工具权限。升级前的旧话题可导入核验后的原元数据，当前接续使用新的本人请求根；不能把旧 topic 直接当成已登记的 request，或让回读消息重新成为 fresh 入站。

## 群回复编排

参与判定可以选择单独答复、合并答复或向缺条件者澄清，同时列明本轮覆盖及暂缓的请求。正文持续明确每项条件与回应对象，多个人的问题不会因共用主题被合成同一个人的要求。

发送前的 `prepare_reply` 只核对实际草稿及已送达片段：回答了谁、还在问谁、用了哪些适用方法。审阅使用本轮冻结且仍有效的公开证据；它不改写正文，不额外发送消息，不把未答的事项标成完成。

只有通道核验过的实际送达 ACK 才提交完成／等待状态及方法使用关系。静默、失败、未知送达、草稿、断线或撤回后的迟到结果不算完成。覆盖审阅失败时保留未完成状态，不静默丢掉原正文。

## 跨天明确记忆

按 [life-memory 跨天明确记忆合同](../plugins/hermes-life-memory/docs/跨天明确记忆.md)保存本人确认的偏好、明确经历及约定。自然“请记住”先提出候选，仍需本人 review／confirm；`/social-memory episode` 可提出明确经历。保存最小语义、原消息来源、确认时间与有效期，不启用原始聊天采集。

好友 DM 使用精确 `dm:peer` 主体，且每次检查真实好友及允许范围。其他好友、同一人的群身份、其他群、主人私人记忆不能互相读取。过期、来源撤回、forget、资格或策略变化会阻止旧资料继续注入，派生回复仅保存 ACK 依赖元数据。

## 有证据的方法学习

`methods.py` 保存具体的“适用条件＋处理建议＋反馈证据”，而非只调整回复长度或频率。自然反馈和显式 `/social feedback` 均须关联本群或本 DM 的实际回复回执；无法核验的用户自报失败不构成学习证据。

达到反馈门槛后生成候选，同一批证据不能重复消耗预算或换 ID 反复试。默认每天每会话最多 2 次生成，失败也计入。遗忘和拒绝使用独立控制栅栏，回滚内容库不会复活旧证据或已拒绝建议。

支持的作者归属、请求分离、接续类别使用预先编写的独立结构化任务。基线与候选使用相同模型、相同 token 上限；基线保留完整既有群聊规则。规则检查器核对事实，模型不为自己的方法打分。未知类别不自动试用。

方法按 `proposed → validated → trial → retained/reverted` 流转。保留至少要求两个独立案例全部通过、至少一个基线失败而方法通过、且至少一个案例发生于开始试用之后。两边都通过只能说明未测出增益，保留有限试用状态，不宣称学会。后续真实负反馈撤销相应方法；来源遗忘会清除建议正文及其派生依赖。

正文只注入本会话最多 3 条、合计 1200 bytes 的有效方法，作为不可信建议而非权限。方法不能增加工具、发送范围、记忆主体或主动目标。

可用命令：

- `/social requests`：当前请求人与未完成状态。
- `/social methods`：方法候选、证据状态与期限。
- `/social try-method ID`、`/social revert-method ID`：可信主人控制群方法；普通好友仅能控制自己的 DM 方法。

## 配置与验证

普通组件默认不开启这些增强项。通过统一入口先检查，再应用：

```sh
python3 scripts/install.py --enhance-social
python3 scripts/install.py --enhance-social --apply --restart
python3 scripts/install.py --enhance-social --check
```

该入口保留既有允许名单、阅读来源、主动目标与原始采集关闭状态，并安装公共上下文合同，防止宿主旧压缩历史绕过语义资料的删除检查。

离线测试覆盖归属、采用、合并／澄清、真实 ACK 回调、重启回读、撤回、旧库恢复、反馈精化、预算及过期。独立真实模型捕获入口如下，均不连接真实 QQ：

- `verify_napcat_social_live.py --enhanced-social`：真实 native worker／FIFO／AIAgent 的合成群消息及正文捕获。
- `verify_crossday_memory_live.py`：确认后服务重建、模拟跨日、好友／群隔离、过期与 forget。
- `verify_semantic_methods_live.py`：明确标注的合成历史错误，真实候选、独立对照、后续正文、ACK 使用和自然负反馈撤销。

捕获验证、已安装文件、实际网关加载、真实 QQ 客户端验收分别报告。跨天捕获使用模拟时间，不等同于实等多天；方法捕获初始错误是公开合成 fixture，不宣称来自模型真实失误。
