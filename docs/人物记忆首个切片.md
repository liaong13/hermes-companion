# 人物记忆 M1 首个实现切片

日期：2026-10-31。承接[互联网生活能力开发方案](互联网生活能力开发方案.md)，本轮交付源码与离线验证，未安装、启用、重启真实网关或修改 `~/.hermes`。这不是完整 M1，也不代表伙伴已经具有持续互联网生活能力。

## 实际行为

在已授权群中，成员以 `/social-memory remember interest|preference|boundary <本人自述>` 创建候选，经 `review` 获取核对码，再由同一真实成员确认。之后回应这个成员时，模型可获得当前群有效的自述；其他成员、同名账号、其他群和私聊不会读到该视图。idle 没有指定本人，仍只使用原有群近期上下文。

新候选不覆盖已确认值，确认新值才原子替换同字段旧值，并记录 `supersedes/revision`。忘记删除来源、资料、证据和索引；原自述消息撤回也会撤销对应资料。已经依赖旧资料的工具授权和发送会再次校验，失效后拒绝。命令响应属于操作通知，不计作社交交流或打开短答窗口。

## 代码落点与接线

| 路径 | 职责 |
| --- | --- |
| [hermes-life-memory](../plugins/hermes-life-memory/README.md) `0.1.0` | 独立 opt-in 服务、原始命令、配置与 profile 生命周期；不注册 MemoryProvider |
| [people.py](../plugins/hermes-scoped-memory/people.py) | 基于 Store 的人物元数据、来源证据、本人核对、修订与受限视图 |
| [social_memory.py](../plugins/hermes-napcat/social_memory.py) | 通道合同 1、精确原始消息控制队列、当前成员上下文与撤销检查 |
| [host_runtime.py](../plugins/hermes-napcat/host_runtime.py) | 公共群回合临时上下文、工具／发送前复验、撤回与断线传播 |
| [adapter.py](../plugins/hermes-napcat/adapter.py) | 复用准入与独立有界控制队列，不放宽普通群管理命令 |

使用正式 `register_platform_handler('napcat', factory)` 接线，不假设宿主具有通用服务注册表。NapCat 更新至 `0.3.3`，存储源码更新至 `0.2.2`；必须安装完整匹配存储目录，旧 worker 单文件副本不足。新增服务不读取 Mem0 数据，也不启用既有 provider。

原始自述按可信成员 ID 保存 `subject_id/asserted_by`，每条资料带伙伴实例和当前来源。资料只在接收者拥有精确 source 许可时加入当前回合临时上下文，保持原始 `event.text` 不变，避免把召回原文再次写进用户历史。现有公开风格宿主接线负责传递临时上下文，无需新增宿主补丁；配置与前提见[组件说明](../plugins/hermes-life-memory/README.md)。

工具回调可能在受限 public profile 下运行，校验读取已安装服务捕获的配置归属，再复验精确 source；环境中的 home 不构成身份。配置变更一经检查就永久撤销旧服务，切回原配置须重新加载；旧卸载回调不能关闭新服务。

当前宿主定向 `unload(owner)` 保留平台工厂列表，可能使旧工厂占用同名 wire key；已确认定向卸载即时撤权，重新附着复验采用 unload-all 后完整重新发现。没有修改宿主 SDK 或宣称任意定向重新启用都可用。
