# 隐私与合成测试资料

源码、测试、示例和分发文档只使用重新编写的合成资料。修复真实缺陷时，可以保留“短答续接”“多人交错”“生成中收到补充”等抽象触发条件；输入文本、参与者、活动和数值应独立构造。

不复制真实聊天原话、地名、人名、账号、路径、时间线或日志。只换掉姓名、城市或账号，仍可能保留可识别的对话片段，不满足这里的测试资料要求。隐私防护断言使用合成 canary，不把真实姓名作为测试常量。实际客户端验收产生的资料保留在用户自己的私有运行目录，不加入仓库。

公开论文、第三方项目的链接与许可证保留真实来源，不将第三方署名伪装成测试数据。源码仓库地址由使用者提供，安装器从当前 checkout 的 origin 生成来源记录，不绑定某个个人账号。

## 检查分发内容与历史

```sh
python3 scripts/check_portability.py
python3 scripts/check_portability.py --history
```

第一条检查当前分发文件；第二条还检查全部可达 Git 对象及匿名作者／提交者信息。历史清理后，作者统一为项目贡献者，邮箱使用 `.invalid` 示例域。仓库本地 Git 身份也应采用相同设置，避免后续提交重新引入个人信息。

针对已有泄露，可在仓库外准备仅自己可读的 JSON 字符串列表，再执行：

```sh
python3 scripts/check_portability.py --history --forbid-file "$PRIVATE_AUDIT_FILE"
```

原始审计词表不得进入 checkout。检查输出只包含文件／对象定位和问题类别，不输出匹配的敏感正文。这类定向扫描只能验证已知模式，不能单独证明资料来源；新增 fixture 仍须审查其合成来源。
