## 前一阶段缺陷修复（历史范围）

- 社交追问按真实出站 reply-to 锚定原消息／发言人，不再按时间上最后一个人猜测；图片结果使用完整路由窗口更新，淘汰或撤回后不恢复。
- 普通 memory provider 可显式接本地 HTTP embedding，回填 active 事实，支持带权限过滤的混合召回及故障诊断。默认关闭，独立 worker 的关键词路径没有自动改成向量路径。
- 个人候选增加原始用户命令核对、确认和拒绝；模型无法确权，证据／策略改变及跨人／来源请求被拒绝。普通群 slash 管理门槛不放宽，群入口仍需带记忆 worker 接线。
- 当前离线复验：social 97 项通过；记忆 207 passed、2 skipped；NapCat 329 项、OK（3 skipped）。跳过条件和合成服务边界见[测试报告](../plugins/hermes-scoped-memory/docs/测试报告.md)。没有真实 QQ 或真实 embedding 模型验收。

关键源码依据：社交插件通过 [register](../plugins/hermes-social/__init__.py) 连接通道端口，[controller](../plugins/hermes-social/controller.py) 默认持有 [RecentContext](../plugins/hermes-social/context.py)，多人候选由 [routing](../plugins/hermes-social/routing.py) 筛选；NapCat 的 [create_adapter](../plugins/hermes-napcat/host_runtime.py) 明确区分两种运行合同；记忆 [register](../plugins/hermes-scoped-memory/__init__.py) 尝试获取 `bound_llm` 与 `bound_session`，其宿主依赖见[集成说明](../integration/hermes-host/README.md)。这些是后续接口设计的实际起点。

## 后续接线需先确定的设计点

1. **记忆读取范围**：群公开事实、当前成员的个人事实和私聊资料分别建模。`ContextProvider` 的公开群 scope 不能借 subject 参数读取私聊；不能只在读取完成后过滤返回值。
2. **写入与确认入口**：谁可将候选确认为群公共事实、撤回如何传播、归档失败如何反馈，都要使用真实事件授权；模型不能自行签发确认权。
3. **生命周期**：先对齐在途提取、删除 epoch、卸载／重载和故障恢复，再决定后台调度；社交状态计数与长期记忆数据库分别管理。
4. **部署验证**：源码、安装副本、活动网关加载及真实 QQ 验收分层记录。模型脚本的 `--live` 会触发外部调用；后续使用前明确数据和费用范围。

真实生产启用、重启或扩大白名单需按具体任务执行；本次评估不更改这些状态。历史行为与当前源码冲突时，更新对应能力表，保留原记录的日期与证据边界。
