# 连续社交、公开阅读与反馈试用

日期：2026-11-01。当前配套版本：`hermes-social 0.4.2`、`hermes-napcat 0.6.1`。本页接续[话题参与研究与实现](话题参与研究与实现.md)，记录 P0–P4 的功能边界和后续多人接续修复；测试、安装副本、网关加载和真实 QQ 客户端验收分别报告。

## 本轮功能

| 优先级 | 已接通的行为 | 主要实现 |
| --- | --- | --- |
| P0 话题与对象 | 批次判断对象、参与／观察／等待；话题关闭、重开、纠正；模型只能选择真实新消息 | `participation.py`、`dialogue.py` |
| P1 连续交流 | 保存话题、参与者、待答引用和机会状态；多人插话后仍能回到原问题；重启只精确回取已登记引用 | `dialogue.py`、`life.py`、NapCat `read_dialogue_refs` |
| P2 主动分享质量 | 实际读取配置内公开 HTTPS 资料，保存时间、来源与摘录；模型结合当前聊天审核并生成短分享，可选择沉默 | `reading.py`、`activities.py`、`life.py` |
| P3 主动开启与接续 | 已授权目标内分享阅读发现，或提起仍有效的未完问题；与既有约定及 idle 共用一次性联系账本、额度和无人回应退让 | `controller.py`、`contacts.py` |
| P4 反馈与改善 | 真实引用或明确命令反馈；多条证据形成保守策略试用，后续回应评估、超时／反证／遗忘回滚 | `activities.py`、`life.py` |
| 普通好友私聊 | 实时核验好友与允许范围，独立受限模型、同好友连续聊天及媒体；保持主人私人路径独立 | NapCat `friend_dm.py`、`host_runtime.py` |

P4 是可审阅、可回滚的有限策略试用，当前只调整冷却倍数、回复长度与分享开关。它不训练模型、不改身份或工具权限，也不等于完整长期关系建模、通用自主创作或任意网站探索。[互联网生活能力开发方案](互联网生活能力开发方案.md)中的更长期目标继续按具体活动交付。

## 研究取舍

- [Inner Thoughts](https://arxiv.org/abs/2501.00383)：分离是否参与与如何表达，保留等待和沉默；本实现不用连续后台思维或固定人格模拟。
- [Social-RAG](https://arxiv.org/abs/2411.02353)：关注有出处、与当前群话题相关的分享。本实现只读取当前聊天配置的公开来源，不能借此搜索其他人的私聊。
- [Generative Agents](https://arxiv.org/abs/2304.03442)：借鉴真实观察、经历、反思和后续行为的闭环；当前先落地有限策略，不把一次规则调节称作完整生活学习。
- 固定版本的多方参与和候选选择代码参考、许可及采纳范围见[前阶段研究表](话题参与研究与实现.md)。网页客户端使用 [aiohttp 官方 API](https://docs.aiohttp.org/en/stable/client_reference.html)；好友消息回读的实际 schema 见[普通好友私聊](../plugins/hermes-napcat/docs/普通好友私聊.md)。

## 配置与安装

统一安装入口见 [INSTALL.md](../INSTALL.md)。普通升级保留功能选择；显式使用 `--complete-social` 才打开本轮主动接续、阅读和反馈试用，且不增加主动目标、阅读来源或原始对话采集。

```sh
python3 scripts/install.py --complete-social --friend-group-members \
  --friend-users 100000004 --friend-media --reading-sources /path/to/sources.json
# 审阅计划后，以同样参数加 --apply --restart 激活。
```

号码为合成占位。好友准入范围是允许名单，加上显式开启的白名单群成员资格；两者均须先证明是当前 QQ 好友。仅同群而非 QQ 好友的临时会话不自动开放。群成员资格来自实际通道查询，不能由昵称或消息正文提供。主动好友目标另用 `--idle-friends` 精确指定，不能从群成员列表自动生成。

`sources.json` 是完整的聊天到精确 URL 映射，例如：

```json
{"group:100000003": ["https://arxiv.org/abs/2501.00383"]}
```

该群必须已经获准观察；普通好友的阅读目标还需符合独立准入与主动目标配置。此文件不含凭据。网页只能使用精确配置的公开 HTTPS URL；拒绝认证信息、非公开 DNS／IP、重定向、压缩及过大响应，不读取环境代理、cookies 或 netrc。每次连接将已核验地址绑定到请求；默认单次 20 秒、512 KiB、两万字符。正文提取是静态 HTML 可见文字／纯文本，不执行 JavaScript 或加载外部样式。

默认每六小时安排一次读取、每日最多三次，失败也消费读取预算；无新 QQ 消息时后台仍可推进。笔记是实际正文的有界摘录，只有抓取成功才算完成。模型分享只能使用该摘录和同场所近期资料，固定附加原始 URL；没有读过的全文不能声称已经读完。

## 连续性与撤销

话题库默认保留一天，未完机会一小时；每聊天最多 32 个话题、256 条消息元数据及 32 个机会。消息正文仅在有界内存中；重启后的回取只接受已登记的最多八个精确引用，核对原角色、作者、时间和真实引用关系。旧机会只有在新消息的真实 ingress 绑定下才重新进入选择上下文，不能复用旧 source 发送。

已确认 QQ 引用与模型判断的话题关联分别保存。未引用的主动接续可以关联逻辑话题，但不会伪造 QQ `reply_to`。只有实际发送并准确回读后才清除待答；未知回执不重试，恢复旧内容库也不能恢复发送机会。

活动、派生回复、反馈和试用均保存来源依赖。撤回消息、忘记公开来源或反馈证据会传播到多跳派生、当前快照、在途回复和策略。发送已进入网络后发生遗忘，外部消息无法撤销保证；迟到回读的派生正文不会重新进入社交上下文。

状态位于目标 profile 的 `plugin-data/hermes-social/napcat/`。`contacts.sqlite3` 保存统一消费；`dialogue.sqlite3` 保存元数据；`activities.sqlite3` 保存获准公开内容、进度和反馈试用。独立的 `*-control.sqlite3` 保留消费与撤销栅栏。备份恢复须保留最新控制账本；同时回滚控制账本不在防复活保证内。

## 查询与反馈

- `/social topics`、`/social notes`、`/social trials`：当前聊天的状态、实际来源和试用。
- `/social read <配置内URL>`：安排读取，不接受任意链接。
- `/social feedback <机器人消息ID> positive|negative|correction`：评价一条实际出站；普通活动不等于回应。
- `/social cancel <机会引用>`、`/social forget-source <来源ID>`、`/social revert <试用ID>`：主人或该私聊本人管理。
- `/social pause|resume|status`：当前场所控制；群内恢复限主人，允许名单内好友可以恢复本人私聊。

自然语言反馈仅在真实引用机器人消息后做无工具分类，不把普通追问推断为满意，不把沉默直接解释为拒绝或关系变化。无回应、明确拒绝和纠正可支持保守退让；保留后的策略仍接受后续反证。试用只在本聊天生效。

## 2026-11-01：多人共同话题的接续修复

群聊按共同话题组织资料。甲提出问题、乙补充条件、丙纠正日期或结论时，选择器和正文生成共同保留话题入口、最近成员补充、实际机器人回答和当前纠正。每位成员使用独立 speaker 标记；任务条件可以共同使用，个人身份、经历和偏好仍属于原作者。并行话题不能仅因同人发言而合并，其他成员之间的交代仍允许保持安静。

重启恢复不再仅回取话题入口和待答问题，也在最多八个已登记精确引用内恢复最近共同条件和实际回答，保留原角色、作者、时间与真实引用关系。点名回复也准备共同话题；原生入口由通道登记的同一个 event/source 证明，仅允许恢复上下文，不把旧 source 或待答机会重新变成发送许可。克隆对象不能取得或撤销原入口，控制命令不额外调用模型。

本轮当前日期按配置时区逐轮读取宿主时钟，参与选择与正文均明确“昨天／今天／明天”。旧会话的 `Conversation started` 仅是起始时间，不能替代本轮日期。选择器只判断是否接话，不以已经知道答案为前提，正文阶段再核对或澄清。此处没有清空或合并成员原生会话，也没有启用群聊原文长期采集。

另修复同轮多个正文片段的许可：已经确认的一段不再撤销当前正在执行的精确 source，仍撤销其他候选和空闲许可。原 deadline、epoch、route 和冻结上下文保持原值；暂停、撤回、遗忘、新明确请求、断线或处理完成仍撤销续发。各正文片段保留同轮来源依赖到处理完成，中途进度不写成完整社交回复。

真实服务端历史、模型最终正文和发送记录已核对一致；所报告的纠错停接案例没有证据表明正文在传输中被截断。发现的是日期使用过期，以及重启后遗漏其他成员已提供的任务条件；片段许可问题作为独立可复现缺陷修复，不充当该案例的已证实根因。

### 0.4.2：回应对象与条件作者分别识别

真人群聊复测暴露了第二类错误：乙提供条件，甲随后指代该条件继续提问，回复却将条件称作甲此前提供。跨成员沿用任务条件与将原话归给当前发言者是两件事。消息 source/quote 的目标正确也不能证明自然语言的作者归属正确；共同主题也不能自动合并每个人各自的请求。

临时上下文新增 `current_request`，明确本轮消息 ID、当前发言者标记与群昵称；各资料仍分别保留原始 speaker，`recent_exchange` 仍只引用当前成员自己的真实请求和实际回答。选择与生成规则区分共同补充、明确接用和独立个人请求；只有前两种情形可以沿用条件，来源不随之改变。历史 self 消息只证明发送事实，不能用其错误说法覆盖成员原始作者证据。不确定的指代会影响任务对象时先澄清。

验证使用独立编写的合成展览寄件与读书会资料，未将真人群消息改名后放入源码。覆盖“乙提议、甲采用但不改作者”“甲乙各自请求不能互填目的地”“甲用指代接用乙建议”，以及既有多人纠错、日期和短答场景。

最终复验：social 303 项通过；NapCat 全量 423 项中 407 项通过、16 项跳过，后续公开上下文 10 项及生命周期 25 项定向复验通过；安装器在实际宿主的一次性 home 中 31 项通过。最终安装副本正式链路真实模型捕获 16/16 通过，真实 OneBot 连接尝试为零，不构成 QQ 客户端验收。232 个 UTF-8 文件可移植性检查零 finding，相关文档 51 个本地链接有效，目标文件 AST、LF、0644 与 diff 检查通过。

中间失败保留为验证记录：选择器未得到本轮日期时曾选择等待，补齐可信时钟后复验；日期夹具曾仅接受 ISO 格式，随后又因最小汉字数拒绝正确的简短中文日期，修订格式断言后仍严格验证目标日期；真实群反馈随后暴露了条件作者误归属，增加上述对象元数据与三个场景。不能把这些中间结果或最终模型捕获视为真人群聊已通过。

0.4.2 已经安装器事务部署，163 个分发文件与源码一致；官方保护在真实回合进行时拒绝重启，等待完成后才成功重载。最终检查为 worker 通过、新网关进程与 NapCat 连接正常。私人 provider、原始对话采集关闭状态、好友准入和既有主动范围保持原值。真实群聊的来源归属与独立请求需要使用这一版本再做真人复测；0.4.1 的真实失败不能作为 0.4.2 的通过证据。
