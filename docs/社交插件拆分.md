# 主动社交组件拆分（实施合同）

本次经用户授权拆分现有已验收行为，不新增加好友、普通群友私聊或长期记忆生产权限，不提交／推送，不从网关进程树重启。保留用户已有暂存区、未提交修改及验证目录。

## 职责

- `hermes-napcat`：可信 QQ 入站、唯一群白名单、真实身份与回执、worker prepare、原目标发送以及来源／工具授权。没有社交插件仍保留原来的点名和主人私聊。
- `hermes-social`：参与策略、近期文本、合并、节流、暂停、空闲机会、公开交流风格与持久社交计数；通过宿主模型 facade 调用原模型／登录，不创建第二个连接。
- `hermes-scoped-memory`：继续承担身份／来源分域的记忆归属。社交运行层预留严格作用域的只读 ContextProvider，不启用尚未验收的长期记忆链路，不把 prepare 校验当成记忆读取。
- bundled Skill：交往方法、配置和验收流程，不是常驻执行器。

## 插件接线

使用现有 `ctx.register_platform_handler('napcat', factory)` 与适配器的 `_wire_plugin_handlers`，不读取另一个插件的私有 manager／模块，不新增核心工具或通用服务总线。适配器明确提供 `participation_port()` 和 `install_participation(controller)` 两个集成方法；controller 不拿 OneBot client、adapter、worker 或原始认证对象。

Social `register(ctx)` 通过其 settings 的 `channels.napcat` 读取已迁移策略；controller 生命周期由本插件绑定，卸载立即禁止可选发言并取消任务。重复接线不能产生两个控制器。独立插件在通道之后加载、缺失、卸载及重连均须测试。

## Port（只由通道构造，不进入模型）

数据：`platform`、`home`、`owner_id`、`groups`（已认证通道群白名单的冻结快照）、`public_name`。

方法：

- `ready() -> bool`；`epoch() -> int`；`recalled(chat, message_id) -> bool`：通道寿命和真实连接状态。
- `issue_optional(event)`：为当前实际候选绑定精确 source、活动代数、连接代数、期限；返回值不授予其他目标。
- `invalidate_optional(chat=None)`：暂停、卸载等撤销可选许可；正常明确寻址不受影响。
- `dispatch_optional(event)`：提交真实事件到原通道的 worker／正式 gateway 链路，不伪造消息或直接调用私人 agent。
- `prepare_idle(chat, task_id, context)`：真实只读 worker 校验该目标的有界资料，不返回长期记忆。
- `claim_idle(chat, task_id)`：仅为本 controller 已声明且通道仍允许的 idle target 签发短期、不透明、单次句柄，绑定真实活动与连接代数。
- `send_idle(grant, text, consume, valid)`：重验句柄、目标、活动、连接及 `valid()` 后，先 `consume()` 持久化消费，再单次发送与准确回读；未知回执不重试。返回 `True/False`，模型只提供 text。

controller 提供 `active`、`policy`、`enabled_for(chat)`、`allows_unaddressed(chat)`、`observes(chat)`、`recognizes_control(chat,text)`、`observe(event)`、`record_self(chat,text,mid)`、`recall(chat,mid)`、`control(event)`、`queue_ambient(event)`、`processing_start(event)`、`processing_complete(event)`、`prompt_for_chat(chat)`、`start()`、`stop()`、`reset_connection()`。策略和状态由 controller 实现；精确来源 ledger 和最终出站检查仍由通道实现。空实现供社交插件缺失时使用。

自然接话默认群范围来自 port.groups，不复制群白名单；策略中的 targets 仅为空闲发言目标。原总开关、安静时段、限频、暂停、合理静默、公开语气和工具表面保持。原 `/napcat-social` 控制命令兼容，独立实现可额外支持 `/social`。

## 验收

成对覆盖有／无插件、禁用／卸载／重复接线、私聊／两个群／两个身份隔离、跨 profile、暂停／撤回／新消息／断线、旧来源与旧 idle 句柄拒绝，普通点名／主人私聊不受影响。运行真实注册工厂、worker、durable FIFO／source codec、AIAgent 与实际模型；只替换 OneBot 为捕获端。安装与活动进程重载、QQ 客户端验收分别报告。
