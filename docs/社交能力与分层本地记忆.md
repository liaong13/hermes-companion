# 社交能力与分层本地记忆

日期：2026-10-31。当前修复以 `历史修订` 为起点。本文区分本次已实现的缺陷修复和后续开发方案；没有启用真实群、读取真实聊天、安装模型或改动运行网关。

本阶段属于[互联网生活能力主线](互联网生活能力开发方案.md)的 M1／M2：先完成社交及相关记忆，再继续阅读、探索、创作、反思与学习。新增研究来源和固定版本代码见[研究与代码参考](研究与代码参考.md)，本地安装／宿主前提见[能力核对](本地Hermes能力核对.md)。
## 当前缺口

现有主动社交提供触发判断、近期上下文、节流、暂停与空闲机会，尚不足以形成持续社交：没有稳定的人物记忆与关系事件，没有持续活动产生可分享的内容，也没有完整的“发现机会→准备内容→核对对象与场所→表达→观察反馈→调整后续行为”闭环。仅增加随机开口频率或扩写人格提示词不能补齐这些能力。

此前四处缺陷已提交。现在独立 [hermes-life-memory](../plugins/hermes-life-memory/README.md) 已实现显式自述首个切片，通过原通道为当前成员提供受限临时视图；话题状态、自动候选、关系事件和完整社交闭环仍待继续。不能把所有群友资料直接拼进每次提示词。

## 本次已完成的四项修复

| 缺陷 | 修复后的行为 | 回归依据 |
| --- | --- | --- |
| 多人插话后追问归错对象 | 跟随真实出站 `reply_to_message_id` 找到原消息和发言人；缺锚点、撤回或后续插话时不猜测 | A 发问、B 插话、机器人答 A 后，只有 A 可按原锚点追问；同一人多话题也绑定原消息 |
| 图片迟到结果只能更新最近 16 条 | 用最多 64 条路由窗口查找原图记录并原位替换，模型展示仍最多 16 条 | 第 17 条后的结果可更新；撤回、过期和容量淘汰后不复活 |
| 普通注册开启 embedding 仍只有关键词 | `local-only` 可显式连接本地 OpenAI 格式 embeddings 端点，回填已激活事实并进行混合检索；缺运行时或故障有状态报告 | 普通注册→本地 HTTP 合成向量→后台索引→同义查询；跨人隔离、代理禁用、删除／策略变更失效与失败退避 |
| 个人候选没有可信确认闭环 | 原始用户命令支持 pending、review、confirm、reject；核对码绑定当前候选和证据，模型无确认工具 | 本人同来源确认后可召回；跨人／群／线程、证据修订／清除、过期、删除、策略变更和重放被拒绝 |

配置与命令见[记忆插件说明](../plugins/hermes-scoped-memory/README.md)，测试命令、结果及 skip 见[测试报告](../plugins/hermes-scoped-memory/docs/测试报告.md)。确认个人候选不会发布为群公共事实。现有合同 4／5 的无记忆路径不会因本次修改自动获得长期记忆。

## 后续社交闭环

1. **识别互动**：在现有可信事件上建立轻量话题状态，区分问题、回答、倾诉、分享、约定与告别，记录正在对谁回应及哪些问题未解决。保留“不参与”结果；不能将短答全部视为冷场。
2. **形成机会**：按当前话题、约定、已知偏好和真实活动生成候选，例如适时追问、延后关心、分享与对方兴趣有关的发现。每个候选携带对象、场所、来源、有效期和发起理由，不依赖通用定时文案。
3. **准备内容**：独立活动获取可核对素材，并留下来源和时间。先从只读活动开始，不增加任意浏览、文件、发送或私人资料能力。活动失败可放弃该机会。
4. **统一决策与发送**：social 统一检查当前话题、时区、暂停、额度、无人回应和最新活动；原通道复核准入、source 与出站能力。发送前预留，未知回执不重试；在途身份、策略或连接变更使旧机会失效。
5. **观察与退让**：真实回复、明确拒绝与单纯无人回应分别记录；无人回应只用于减小联系频率，不推断“讨厌我”等关系结论。停聊、忘记或撤回后取消相应机会。

当前版本已有部分节流／退让组件，但尚未实现以上完整闭环，也没有新接入参考项目的 B 站、画图或其他活动。

## 独立本地人物记忆的分层

人物记忆的“层”描述内容和生命周期，权限仍由来源与可见范围独立决定。建议按以下顺序实现：

| 层 | 保存什么 | 生命周期与社交用途 |
| --- | --- | --- |
| 临时互动 | 当前话题、待回答问题、最近回复对象 | 短 TTL；支持接话，结束／撤回／断线后失效，延续现有近期上下文 |
| 情景与事件 | 一次共同讨论、已明确的安排、尚未完成的约定 | 保留发生时间、来源与状态；用于在合适时机续接，不把过期安排当现状 |
| 稳定个人事实 | 对方自述的称呼偏好、兴趣、沟通偏好等 | 候选→本人核对→生效；支持修改、到期复核、拒绝与忘记，昵称不充当主键 |
| 关系与互动偏好 | 对方明确表达的联系边界、称呼与互动方式 | 明确表达优先；模型推断单列为未确认假设，不自动改变权限或形成确定关系 |
| 已批准的场所公共事实 | 可在特定群／线程引用的共同背景 | 独立批准／贡献撤回与版本机制；与人物私有事实分开存储和检索 |

事实模型至少区分 `subject_id`（说的是谁）、`asserted_by`（谁提供）、`source_id`／消息修订、发生时间、有效期、状态、置信度和可见范围。第三人“某某喜欢……”只是该人的陈述，不能直接变成某某已确认的资料；旧信息与新自述冲突时保留证据和修订过程。

真实成员 ID 来自通道已验证事件。跨群同一账号可以指向同一人物标识，但不自动获得跨场所读取权限；同名、昵称变化或文本自述不能合并不同账号。当前 scoped-memory 按“贡献者＋来源”隔离，尚没有上述完整 `subject_id` 人物模型，不能用标签或改 SQL 绕过隔离来假装已经实现。

本地保存也不等于不会出站：召回结果如果进入对话模型，就按当前输出场所和模型出站策略审核。群 idle 没有当前成员主体，只能使用该场所已批准的公共资料；不得借主人身份、最近一个发言人或目标人物参数读取私聊记忆。

## 插件之间如何连接

新的人物分层插件负责事实、证据、确认、修订和删除。social 负责何时参与和联系节奏；通道负责真实身份、事件与发送。先形成版本化接口和行为测试，再选择复用当前 scoped-memory 的内部模块还是新增存储适配层，不先复制第二套数据库。

社交侧只提交获准的当前场所、已验证参与者、话题和用途；记忆侧在读取前决定可见范围，返回带出处、时效与可见标签的最小结果。API 不接受模型提供的任意 owner／domain，也不将原文或整个人物档案作为默认结果。忘记、撤回或策略变更要能撤销近期缓存、在途检索和关联的社交机会。

## 下一笔开发的验收切片

先交付“同群人物自述→候选→本人核对→按场所召回→忘记后不再引用”，使用合成身份和文本验证，不直接上线全部自动提取。同步固化话题／回复对象状态，让人物记忆真正服务于续接交流。

验收至少包含：同名不同人不合并；自述与第三人陈述分开；跨群／私聊不能借同一账号读取；群 idle 无个人主体；本人修正后不再注入旧值；忘记与在途任务竞争不能恢复旧资料；模型输出确认命令不生效。通过后再增加带来源的只读活动，以及统一联系账本下的一种主动分享场景。

真实中文向量质量、主动参与的打扰程度、信息引用准确性及多人 QQ 客户端表现，需要另行在授权测试环境验收；本次合成服务与 namespace 测试不代替这些结果。
