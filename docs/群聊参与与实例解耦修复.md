# 群聊参与与实例解耦修复

日期：2026-10-31。本文记录源码修改及验证，不代表已安装、重载或完成真实 QQ 验收。

## 本轮结果

`hermes-social` 定位改为互联网生活运行层；当前交付仍是交流和约定联系活动，保留插件 ID、配置与数据路径。通用活动执行器、版本化自我模型和反思回用尚未实现，完整路线见[开发方案](互联网生活能力开发方案.md#运行层定位与自我模型)。

框架不预设具体角色身份。NapCat 单次问答的固定角色描述、默认触发名以及强制语气模板已移除。名字触发模式必须显式提供呼唤名，该值不进入生活决策提示词，也不作为自身发言的身份标签。可选 `public_self` 是实例的初始公开资料，支持 `name`、`description` 和 `communication_preferences`；它不读取私人 SOUL，不提供系统提示词覆盖，也不等于已经接通自主成长。

保留的固定指令限于任务协议、输出结构和真实执行边界。具体观点、兴趣、关系判断和表达偏好不再由框架指定。配套 Skill 已同步移除旧的语义筛选流程。

## 群聊为何漏接及如何修复

此前存在三个相互独立的问题：模型前的措辞筛选拦住分享、短答及不含疑问词的请求；群内个人会话没有得到共同公开语境；模型生成期间，普通补充消息又使可选发送许可失效。不能用提高 idle 每日次数处理这些问题。

本轮改动如下：

- 自然文本经有界合并和节流获得模型判断机会，删除疑问词、群邀请词、短答词表和主题字面重合筛选。真实 @ 或经核验引用给其他成员的消息不触发可选回复，但可作为背景。纯媒体仍走原媒体通道。
- 点名与可选群聊均通过临时上下文钩子取得同群十分钟内最多十二条公开观察，整个快照不超过 5000 UTF-8 字节。使用临时发言者别名区分同名成员；原始用户文本保持原样，不把资料附写为用户指令，不读取私人或其他群资料。
- 保存真实请求与实际出站回复的对应关系。紧接当前发言者的真实来回可提供续接线索；有人插话后仍保留记录，但不再认定本条必然属于那段交流。意图、回应方式和 `NO_REPLY` 由模型选择。
- 生成中的普通公开活动在发起后二十秒、最多八条内不自动撤销文本回复；原 source、目标、连接代数及许可期限不变。明确新请求、控制、暂停、撤回、断线与卸载仍撤销可选许可；媒体保留更严格的失效规则。
- 撤回和显式忘记会撤销依赖该资料的快照，包括原资料已从内存窗口淘汰的情况。普通淘汰或生活插件卸载不会误伤已准入的正常点名回合。

新生活控制器要求通道 `public_context_contract=1`，混用旧通道时在启动任务前拒绝，避免悄悄丢失公开上下文。日志增加候选观察、合并、选择、失效及未发送原因，只记录路由元数据和原因码，不记录正文。

本轮没有增加断线历史回放。网关离线期间未收到的 QQ 消息，不能凭这些修改恢复；可靠补收需要另行设计可信历史来源、去重和已处理／已发送对账。

## 验证与限制

- 生活运行层离线测试：108 项通过。
- NapCat 离线测试：356 项，16 项因前提不满足跳过，其余通过。
- 可丢弃宿主覆盖层：本地记忆 6 项、约定联系 7 项、宿主临时上下文 4 项通过。
- 安装及隐私工具测试：23 项，2 项跳过，其余通过。Python 语法、差异空白、文件模式和换行核对通过。
- 全合成 `synthetic-authored-v2` 真实模型组合：8/9 场景通过。测试只使用独立构造的合成活动、选项和计分规则；经过真实 worker、durable FIFO、source codec 和 AIAgent。短答、独立身份和跨成员规则理解通过；一例仅从文本指向其他成员的请求出现误插话，仍待修复。OneBot 连接尝试为零，发送由捕获端接收，凭据未写入测试产物。

早期曾记录九场景通过，但原夹具未满足全合成资料要求，已经替换，旧结果不作为新夹具的验收结论。当前失败没有改为预期回复或放宽判据。任何单组通过也不能证明所有群聊情境都能正确判断，更不能等同于长期学习或生产回复频率已改善。资料与历史处理见[隐私与合成测试资料](隐私与合成测试资料.md)。

下一切片以“经历与实际结果→带证据的反思候选→小范围试用→后续选择变化→保留／修订／撤销”为验收对象。对他人的事实、自己的印象及自我模型分别保存，继续使用本地存储、检索和删除；不以追加人格提示词、扩大权限或增加记忆条数代替成长。
