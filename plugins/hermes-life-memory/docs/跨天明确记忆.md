# 明确授权的跨天记忆

本切片使用既有 scoped-memory Store、PeopleMemory 与 Relations，保存本人明确授权、经本人核对的兴趣、交流偏好、联系边界、经历陈述及约定。不会开启全量聊天记录、扩大私人 Mem0，或把十分钟 RAM 缓冲变成长期记忆。

## 配置与原文边界

配置仍位于 `plugins.entries.hermes-life-memory.settings.memory`，示例号码为合成值：

```yaml
enabled: true
instance_id: companion-demo
domain_id: people-demo
policy_revision: 1
groups: ["20001"]
friend_dm: true
explicit_memory:
  enabled: true
  ttl_days: 30
conversation:
  enabled: false
candidates:
  enabled: false
episodes:
  enabled: false
agreements:
  enabled: true
  proactive: false
```

`friend_dm` 与 `explicit_memory.enabled` 默认关闭。好友功能另需 NapCat `friend_dm` 显式准入及实时好友／群成员资格，不能用此配置授权陌生人。允许群与普通好友范围不相互复制；主人原私聊继续原私人路径。

原始采集关闭时，`remember`／“请记住”只留候选所需的逐字片段、来源消息 ID、原文偏移及时间；`plan` 只留明确时间和约定片段。普通提问、普通自述、正文回复和模型推理不会进入 Store 的原文来源表。回复的派生依赖另留无正文元数据，供遗忘撤销，不能用来重建聊天原文。

## 本人确认与语义候选

发送 `/social-memory remember preference <本人偏好>` 或“请记住：我喜欢合成纸卡工坊”后，只生成 pending 候选。`review <ID>` 显示原文证据、有效期、场所与核对码；同一真实成员在原场所执行 `confirm <ID> <核对码>` 后才召回。

本地规则能提取时不调用模型。只有明确第一人称记忆请求、规则无法覆盖时，适配器才使用现有 `ctx.llm`，输入仅本轮原文及固定提取规则，无工具、私人上下文或其他好友资料。模型只能选择 `interest/preference/boundary/episode` 和真实连续原文 quote；伪造、歧义、缺失或超预算片段不落库。模型输出不构成确认，候选始终待本人核对。

明确共同经历可用 `/social-memory episode 我们在合成工坊核对过纸卡编号`。确认后记录为 `subject_confirmed_statement`，只表示该成员认可自己的经历陈述，不替其他参与者确认，也不宣称外部事实已验证。最多保留当前范围内 8 条有效或待确认明确经历；召回受现有少量关系资料预算限制。`episodes.enabled=false` 仍不影响这些明确授权候选，也不会开启自动摘录。

他人复制核对码、同名昵称、群里的身份、自报 QQ 或转述不能替另一人确认。scope 由通道构造为 `(domain, napcat:本人, group:群)` 或 `(domain, napcat:本人, dm:同一本人)`；人物资料同时校验 `subject_id == asserted_by == 当前 principal`。

## 召回、时效与撤销

确认事实可跨天和进程重启召回，仍只在原场所回应本人时使用。当前只返回该精确 subject 的少量有效字段，避免只凭关键词遗漏交流边界。每条包含原消息 ID、逐字证据、观察时间、确认时间和失效时间；历史偏好不得当成永久事实。新事实按配置有效期（默认 30 天，范围 1–365 天）生效，不因召回而续期。

约定使用 `/social-memory plan <带时区ISO时间> <约定>`，本人 review／confirm 后可在原群或原好友 DM 的后续回合召回。时间必须在未来 90 天以内；到期、取消或过期不等于外部任务已完成。好友 DM 约定不自动授予主动联系权限。

每次好友控制和召回前，适配器强制复核真实好友及适用群成员资格；发送前再次复核。来源撤回、forget、过期、修订、配置／policy 变化会使临时 view 失效，阻止迟到回复。忘记会沿无正文依赖撤销已发送 ACK 在 RAM 中的派生回复；旧内容 SQLite 恢复仍受独立删除账本清理。正常卸载与重启不会删除仍有效事实；策略调整会退休旧语义来源，不把旧候选重新激活。

控制消息和 review 输出不进入 social 近期聊天，也不作为新的正文记忆。已经发送到 QQ 或外部模型服务的数据不会因此从外部删除；本机制处理本地证据、召回和后续使用。

正式 ACL 或记忆策略变动应保持 `policy_revision` 单调递增；只有实际被服务观察的变动才能触发退休，不能靠未观察的关闭再恢复相同旧配置表达永久遗忘。临时离线或好友资格缓存过期会禁止召回与发送，不自动删除已有本人授权资料。可信 `friend_recall` 则通过精确本人 DM 的仅删除路径处理，即使当前资格缓存已过期也能撤销旧证据；该入口不赋予读、确认或发送权限。

## 接线契约

- `LifeMemoryService(..., dm_allowed=callback)`：callback 来自当前 ParticipationPort，只有精确当前好友 DM 返回 True；服务每次 scope 与 view 检查都复核。
- `propose_explicit(route, text, {field,value,start})`：只接受本轮明确请求和精确原文 span，复用原候选／确认／删除机制。
- `recall(route, include_conversation=False)`：返回 confirmed `facts`、`relations` 中的经历与约定、原证据／确认时间／有效期及 `current()` 撤销 fence。
- `record_reference_delivery(route, ack_id, view)`：只写来源依赖元数据，不存正文，防止 forget 后从旧回复重新引用。
- NapCat `_friend_memory_control(event, raw)` 在 social.observe 前识别控制路径；控制仍由受限好友任务执行，不能转入主人 agent。
- `_prepare_friend_memory_context` 只向本好友当前正文提供临时资料；`prepare_reply(event,text)` 仍由 social 审核已生成草稿，记忆控制不调用它。

测试全部使用合成来源与临时 home：service 测试覆盖跨天／重启、TTL、场所与本人隔离、旧 DB 恢复、策略变更和无正文依赖；NapCat 测试覆盖实际控制入口、自然候选、忘记后的短期历史、可信撤回通知（含好友资格缓存过期）和 group/DM 同域接线。

## 真实模型捕获验收

独立脚本 `integration/hermes-host/verify_crossday_memory_live.py` 接受显式 `--live --host <Hermes源码> --owner-home <当前profile>`，以及可选的 `--plugin-root / --social-plugin-root / --life-plugin-root` 用于核对已审阅的源码或安装目录。脚本仅通过官方只读 resolver 取现有模型路由，credential 通过 `scoped_runtime_main` 与 auxiliary resolver 内存接缝注入，不复制 auth、私人身份或历史。

六个场景使用真实模型正文和合成资料：A 本人确认偏好后重建服务、A 本人确认经历与约定、同名 B 隔离、同人在群中的隔离、忘记后旧 bot 回复不回流、过期资料不复用。好友五场景走实际受限 ingress 和真实分类／正文；群场景仅为 `convert_event → service 精确group scope → 同ctx.llm正文` 探针，不是完整 native worker 验收。候选使用本地精确规则或明确命令，报告会如实标记。OneBot 好友名单、身份、消息和 ACK 均为捕获夹具，脚本禁止真实连接。

报告保留实际 facade/wire 入模消息、真实 provider/model/API 调用数、来源 scope、组件路径、无工具与凭据不落盘检查。该验收补足真实生成证据，仍不代表真实 QQ 客户端验收。
