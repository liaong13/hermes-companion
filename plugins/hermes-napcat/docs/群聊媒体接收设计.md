# 群聊图片、文件与语音接收设计

自有文档 MIT。2026-10-27 已按新授权补充仓库实现、中文接入文档与自动化测试；未部署、未做真实群媒体或付费模型验收。当前可执行能力、真实配额和配置见 [媒体实现与验收](媒体实现与验收.md)。本文保留原设计目标与协议研究，未落地提案不当作现有功能；公开模型目录快照不是效果实测。不改生产配置、已安装插件或白名单，不重启网关，不提交或推送。

## 1. 目标与现状

支持三个入口：同条真实 @ 消息携带媒体；真实 @ 并引用同群媒体；经管理员显式开启后，真实 @ 指定“我刚发的图／文件／语音”。出站继续纯文本，不在本轮实现发送附件、视频理解、合并转发递归解析或全群自动识别。

默认关闭时 `convert_event` 仍将媒体转成 `[unsupported:image]` 等标记，返回 TEXT，不传媒体文件。仓库新增可选 strict v2 接线：真实@或显式正文名称触发的附件／单层引用在域准入后异步处理。无触发消息不进入聊天，观察模式另行有界索引。WebSocket 继续负责事件与echo响应，下载与模型任务独立调度。正常factory接线及provider费用模式已补齐，见 [测试部署接线](测试部署接线.md)；下文原方案中的拟议项不是现场启用证明。

仓库的 strict 隔离实现与线上 legacy 版本不是同一个部署状态。必须继承 [接入与隔离设计](接入与隔离设计.md) 的域隔离，不能为了看图绕过 bridge 或退回私人 agent。媒体上传云端是新的数据出站权限，不因群或用户在白名单就自动成立。

## 2. 总体方案

推荐“安全接收层 + 可替换识别层 + 原有对话模型”，不把主聊天模型换成 Qwen-VL。

流程：可信 OneBot 事件 → self_id／用户／群 ACL → 触发判定 → 精确域准入 → 受限引用解析 → 媒体句柄 → 安全获取与格式核验 → 图片／文档／音频 worker → 带来源的非可信结果 → 原会话回答。

解析顺序和最终回复目标由程序固定，模型不能指定下载 URL、宿主路径、群 ID、任意消息 ID 或提供者密钥。文本与媒体按原始 segment 顺序保留，混合消息部分失败不吞掉有效文字。下载、解析和模型操作各自有独立错误码，不用一个“看不了”覆盖所有阶段。

原方案按下列职责拆分；本次实现合并为 `media.py`（策略／引用／索引／编排）、`media_io.py`（获取／沙箱）、`media_worker.py`（解析／Whisper）、`media_provider.py`（辅助模型与预算），而非以下拟议文件名：

- `media_policy.py`：开关、出站权限、配额、scope 和可接受 MIME。
- `media_refs.py`：MediaRef／Artifact／RecognitionResult、引用和候选绑定。
- `media_resolver.py`：限定用途的 OneBot 只读查询和响应校验。
- `media_fetch.py`：下载及安全复制，不能提供通用 URL 下载工具。
- `media_workers/`：图片规范化、文档提取、语音解码，隔离运行。
- `media_provider.py`：OpenRouter vision/audio 调用、费用控制、结果规范化。
- `media_store.py`：短期句柄、任务状态、撤回与清理，不调用私人记忆库。

## 3. 触发与引用策略

### 同条媒体

要求当前群和发送者都通过 ACL，且当前消息有真实 at segment。图片、文字和多附件构成一个任务；附件不是单独的自动回复请求。纯语音或群文件上传通常不能同条 @，由后述引用／候选机制补足，不关闭 mention gate。

### 明确引用

当前触发消息通过准入后才允许查询被引用消息。引用深度最多一层，附件总数照常受限，禁止递归 forward。返回结果必须有可信同群证据；若 `get_msg` 不返回可校验群来源，必须由该群先前事件索引证明，不能仅因一个全局消息 ID 存在就放行。

初始范围只允许引用同群、仍被媒体来源策略允许的发送者；缺失来源、跨群、私聊、机器人自发敏感附件或过期索引均拒绝。后续若允许引用非用户白名单成员的内容，须独立批准“群可见内容读取”策略，不能偷偷扩张原用户 ACL。

原附件作者与当前请求者分别保留；不得把附件文字或转写结果冒充请求者刚说的授权指令。

### “刚发的那张”

默认关闭，需显式启用 `observe_metadata`。开启后，只有通过 self_id、群和发送者 ACL 的非 @ 媒体事件才能建立短期、内存有界的最小索引；不下载、不识别、不调用模型、不写入记忆，不建立普通 agent 会话。

建议窗口 120 秒，同一发送者、同一群、同一机器人账号内最多保留 10 条记录。只有当前明确 @ 请求分析对应媒体时，才在用户选定类型内寻找唯一候选。多张或多个文件必须让用户引用确认，不猜“最近一张”。其他成员、跨群或重启前记录不自动关联；历史 API 不作默认兜底。

若未启用观察，明确回复“请引用那条消息并 @ 我”，不声称已有图片。被动接收群事件不等于授权保存其全部内容。

## 4. 内部合同与 Hermes 接线

MediaRef 至少包含：机器人账号、platform、不可变 route/domain/policy_revision、chat_id、原消息 ID、原发送者、触发消息 ID／请求者、segment_index、种类、受限 OneBot opaque handle、收到时间、过期时间、触发依据。名称与 URL 均为非可信元数据，不能决定路径或路由。

Artifact 包含随机 artifact_id、scope、内容摘要、实际 MIME、字节数、规范化文件句柄及有效期；路径由程序生成。摘要用于同 scope 去重，不允许跨用户／跨群内容寻址命中。模型只接收本任务获准的文件或像素，不能访问缓存目录。

RecognitionResult 保留 artifact_id、来源、识别方法、model/provider、耗时、usage、页码／音频时间段、文本及可读性警告。模型自报置信度不是校准准确率；不清楚就标记不清楚。结果属于非可信内容，不是 system 指令、管理命令、身份认证或长期记忆。

本机宿主 `gateway/platforms/event.py` 支持 `media_urls`（注释明确为本地文件路径）、`media_types`、`media_text_inlined`、PHOTO／DOCUMENT／VOICE／AUDIO 以及引用字段。三个数组按宿主合同保持索引一致，不把远程 QQ 链接直接塞进去；已有 closed ingress metadata 合同不允许随意新增自定义字段。

设计中的两条接线路径；本次只启用第2条的 strict v2 派生文本合同，第1条仅做原生字段准入验证：

1. legacy 宿主兼容验证：安全获取后的任务专用本地文件通过上述原生字段进入宿主，核验混合 MIME、无重复内联、取消与缓存迁移；测试 native ingress 是否接受每个字段。宿主已有 `rehome_inbound_media`，但它不替代域授权。
2. 推荐 strict 路径：在 Admission 确定后，通过版本化 bridge/worker 合同仅传 scoped artifact handle 或受控只读单文件，不给隔离 worker 主人 home 或整个媒体缓存。现有 worker 不因本文自动支持图片；必须扩展请求 schema、大小限制和多模态提供者调用，单独验收。

Hermes 官方支持原生视觉输入，也支持 `auxiliary.vision` 辅助模型。但视觉主模型可能直接获得像素，显式辅助模型并不保证每次都被使用。若必须让所有图片先过指定 Qwen-VL，需明确接入模式并验证宿主路由，或在 strict media service 中调用该模型后仅交识别结果；不能声称改两个配置就能修复 NapCat。

## 5. 图片处理与模型选择

图片先做字节数、magic/MIME、一致性、像素及帧数核验；采用受限进程重新编码，去除 EXIF 和非必要元数据。普通照片生成受限长边预览；长截图／表格使用有限分块并保留坐标和顺序，禁止一律压小导致中文不可辨认。首期 GIF 仅取首帧并告知，SVG／未知格式默认拒绝，不在群里还原原始路径或签名 URL。

本轮通过 OpenRouter 公开 `/api/v1/models` 实际查询，以下模型均列出 image 输入；这仅证明目录声明，不证明实际账户额度、特定 provider 在线或效果。完整快照见 [公开模型目录快照](references/openrouter-media-models.json)。

| 用途 | 模型 ID | 目录输入/输出美元每百万 token | 选择依据与限制 |
| --- | --- | --- | --- |
| 默认候选 | `qwen/qwen3-vl-30b-a3b-instruct` | 0.15 / 0.60 | 优先评测中文截图、OCR、群表情语境；不能把参数规模当效果证明 |
| 复杂图升级候选 | `qwen/qwen3-vl-235b-a22b-instruct` | 0.21 / 1.90 | 小字、复杂表格与图表的待测升级项，不默认每张双跑 |
| 轻量对照 | `qwen/qwen3-vl-8b-instruct` | 0.25 / 0.75 | 本次目录价反而高于 30B，不能因模型小就声称更便宜 |
| 跨模型对照 | `google/gemini-2.5-flash` | 0.30 / 2.50 | 目录同时声明 image/audio/file，实际端点需单独验证 |
| 图文对照 | `openai/gpt-4.1-mini` | 0.40 / 1.60 | 图文识别备选，目录无 audio，不能拿来直接转写语音 |

以上不是每张图片价格；图像 token 化、路由端点、缓存、OCR 插件费用另计，以上不包含免费或可用性承诺。首期不选 thinking 为默认，先以准确性、时延和实际费用比较 instruct。优先单模型处理，结果缺漏或用户要求时才升级。限额不足、无 image 能力或不允许的数据路由应明确失败，不偷偷更换供应商或公开图片。

OpenRouter 图片请求用 `/api/v1/chat/completions`、正文先文字再 `image_url` 内容块，图片采用规范化后 base64 data URL，不把 QQ 临时签名链接发给第三方。主任务提示只带用户问题与必要上下文，不把群历史、主人记忆、凭据发给视觉模型。

## 6. 文件处理

文件上传通知不能直接生成聊天请求。先记录合规的最小文件句柄，之后由当前合法 @ 请求明确选中；不枚举整个群文件目录。图片附件按图片流程，而不是只凭扩展名分流。

首期支持 UTF-8 文本／Markdown／CSV、PDF、DOCX、XLSX；PPTX 后续加入。PDF 优先本地文本层，扫描页以有限渲染＋OCR／VL 处理；DOCX 提取段落与表格，XLSX 保留工作表和单元格坐标、公式仅展示不执行。文本保留行号、PDF 页码，答案引用对应位置；缺页、截断及 OCR 页范围必须显式标注。

解析器运行于无网络、无主机 home、无密钥的独立 worker；禁止宏、外部实体、外链解析、shell、Office 自动化和主动内容。OOXML 属 ZIP，必须限制条目数、解压比与总展开量；首期不支持普通压缩包、可执行文件、加密文件、旧式 Office 二进制或任意插件自动安装。附件不能自动触发技能安装或命令执行。

默认本地抽取＋按需发送抽取片段给对话模型；不把全部文件自动上传云端。OpenRouter 支持 PDF file 输入与 file-parser，但可能引入额外解析方和按页费用，只有额外允许时使用，必须显式指定引擎，不能依赖平台自动选择。qwen3-vl 的目录 image 能力不等于原生 DOCX／任意文件能力。

## 7. 语音处理

语音 segment 先解析为受限句柄；取得音频后探测真实编码与时长。QQ 语音可能需要 SILK/AMR 等转换，不能假定改成 `.wav` 就是 WAV，也不能假定 ffmpeg 一定支持该 SILK 变体。优先评估 NapCat `get_record` 的转换能力，实际版本不可用时才用沙箱内经审核的解码器；无法解码就明确提示重新发普通音频文件。

归一化为 ASR 端点支持的格式（如 PCM WAV），先检测静音、截断和时长，再转写。首期只做语音转文字，再交原对话模型；不推断声纹身份，不靠声音授予权限，不默认输出语音或伪造情绪判断。

ASR 方案 A：复用 Hermes 支持的本地 faster-whisper 或已配置云 STT，需验证 strict 域可用性、资源和出站权限。方案 B：OpenRouter 音频模型（当前目录 Gemini 2.5 Flash 有 audio），使用 base64 `input_audio`＋明确 format；OpenRouter 音频输入不支持直接 URL。Qwen3-VL 这几项只有 text/image，不能当 ASR。音频模型是否能做好中文、方言、噪声、专有名词，需要真实语料评测，不能以通用 multimodal 标识替代。

转写保留语言、时间段（若实际提供）、不清楚片段和截断提示，不虚构逐字时间轴或置信度。转写内容是附件引用，不是新的操作授权；像“删除所有文件”这样的语音不得自动变为管理命令。当前触发消息与原作者分别保留，`allow_gateway_control` 对派生内容禁用。

## 8. 下载、隔离与隐私

OneBot 连接鉴权不等于返回的 URL／路径天然安全。HTTPS 下载仅允许部署时审核的 QQ 媒体域名；禁止 URL 凭据、非批准端口、代理环境、任意重定向、回环／内网／链路本地／元数据地址，包含 IPv6 和 IPv4 映射形式。DNS 校验必须与实际连接绑定防 rebinding；如需重定向逐跳同样审核，初版直接禁用。不得把 OneBot token 或 OpenRouter key 转发给媒体主机。

签名 URL 若实际使用 HTTP 或非白名单域，默认拒绝，优先通过受控媒体服务解决，不能为兼容而允许任意公网 URL。具体 QQ CDN 及协议需部署实测，本文不虚构通用域名白名单。

NapCat 可能运行在容器中，返回路径不等于宿主路径。禁止对事件中的路径直接 open。若使用共享目录，必须是预配置单独的媒体出口，不挂载整个 NapCat profile；拒绝符号链接、路径穿越与 TOCTOU，安全打开后 fstat 校验普通文件，以 FD／安全复制流交付。否则通过受认证、限定句柄的中介流获取；未落实安全传输就不支持该模式。

下载以真实累计字节计限，不信 Content-Length；有连接、空闲和总时限，取消必须终止下载、解码和模型任务。缓存按账号／域／群／用户隔离，默认文件 0600、目录 0700；短期索引不保存永久签名 URL，不跨 scope 复用摘要缓存。

媒体不自动写私人 Mem0、公共群记忆或向量库。识别内容如后续要记忆必须走现有 scope 策略和单独确认。撤回／删除清本地候选、原件、派生文件与识别缓存并停止未完成任务；已送云端内容无法承诺撤回，保留期限／数据训练政策取决于选定 provider。群回复会对全群公开，敏感内容先提醒，不因请求者有权限就自动公开全部证件或凭据。

## 9. 拟议默认配额与配置

所有数值均为待压测的设计起点，不是当前运行设置或供应商限制：每请求 4 个附件；图片每个 10 MiB、解码上限 32MP；文档每个 20 MiB、总页数上限 100，初次最多处理 20 页；音频每个 10 MiB 且不超过 120 秒；文本提取最多 100,000 字符，超过则明确分段／截断；全局并发 2、每群并发 1、待执行队列 16；获取总时限 30 秒、解析 20 秒、模型 60 秒；任务总时限 120 秒；原件及派生文件 TTL 1 小时、总缓存 256 MiB。图片帧数、OOXML 展开量、ASR 内存和解码输出另行硬限。

总体积限额、磁盘高水位及大文件流式拒绝必须先于调用模型。默认local费用模式要求持久预算预占与实际结算，超限拒绝新调用；只有部署者明确选择provider模式才依赖供应商key额度，不自动把缺预算字段当无限制。超时但计费未知不自动重试。provider返回有效usage/cost才作为其报告费用，否则记unknown；不从本地配置推断供应商额度生效。

拟议配置命名空间 `platforms.napcat.extra.media`：`enabled=false`、`image.enabled`、`file.enabled`、`voice.enabled`、`references.enabled`、`observe_metadata=false`、`cloud_upload.enabled=false`、允许群／类型／provider、配额与预算。图片 provider/model 拟为 openrouter 和 qwen/qwen3-vl-30b-a3b-instruct；音频独立 asr.provider/model，禁止复用视觉模型字段。现有 `auxiliary.vision` 仅用于经验证的宿主路径，不与插件字段混作双重真值。

以上是原 schema 提案，不是本次闭合 schema；实际支持键以 [媒体实现与验收](媒体实现与验收.md) 及 `examples/config.disabled.yaml` 为准，不接受未知键。凭据只经网络层受控环境注入，解析 worker 不继承凭据。禁用媒体退回明确“不支持附件”状态，不改变文本 ACL。

## 10. 失败、并发与恢复

状态：RECEIVED → AUTHORIZED → REFERENCED → FETCHED → VALIDATED → RECOGNIZED → DISPATCHED → REPLIED；终态含 REJECTED、EXPIRED、CANCELLED、FAILED。并发完成结果仍按原始 segment 排序；任务幂等键至少含 account、domain、chat、触发消息、原消息、segment、policy_revision。重连不得重复收费或重复回答。

回复闭包绑定当前群和触发消息，过期／取消即撤销。不允许后台媒体处理任务在 strict dispatch 返回后继续发送。重启前未完成任务默认标失败，不宣称 exactly-once；持久恢复属于另行实现的状态合同。部分附件失败时明确指出序号和错误，但有效文字／附件可以继续处理。

用户错误应区分：未授权、引用跨域或无法确认来源、候选歧义、链接过期、格式不支持、超限、解码失败、转写不可辨认、提供者限流／余额不足、任务取消。日志仅记录随机关联号、类别、大小桶、耗时、错误码、选定模型与费用统计；不记录完整正文、base64、QQ 号、签名 URL 或完整第三方响应。

## 11. 实施顺序与验收

P0：冻结协议版本，定义合同和云数据权限；先测 ACL 和 strict bridge，不开真实云识别。

P1：同条 @ 图片 → 安全获取和图片 worker → OpenRouter 视觉辅助 → 原对话回复。继而加入单层引用；通过实测再开放 opt-in 候选索引。

P2：文件 notice 接入、按句柄选取、文本／PDF／OOXML 沙箱提取和页码引用。

P3：语音获取与解码、ASR、文本回注；最后评估 Gemini 等音频路径与本地 ASR 的准确率／延迟／隐私取舍。

验收需分层记录，不能把合成事件通过称为真实 QQ 可用：

- 协议：图片／语音／群上传文件真实 payload；同条、引用、单独非 @ 和撤回。
- 安全：未授权零下载零模型；跨群 ID、伪造 CQ、路径穿越、软链接、DNS rebinding、重定向、解压炸弹、超像素、恶意宏和提示注入；解析进程无密钥／私人 home／网络。
- 合同：mixed MIME、数组长度、纯附件、原生准入拒绝、strict worker 多模态 schema、跨域缓存不可见、取消／超时后不能发消息。
- 模型：中文截图／长图／表格／模糊图、扫描 PDF、普通话／方言／噪声语音，用获准的非敏感固定样本；记录 OCR 字错率、问答正确率、ASR CER、真实用量、端到端 p50/p95。样本与阈值先约定，不虚构模型排名。
- 稳定性：并发顺序、队列满、断网、重复事件、重启、限额和 TTL 清理；未知计费不无限重试。
- 端到端：真实授权账号在客户端核对附件来源、识别内容、最终群回复、费用与隔离；无此步骤只能标“设计／自动化通过”。

## 附录 A：协议核对与实现约束

以下依据 OneBot 官方规范及 NapCat 官方仓库源码静态研究；父任务直接重取核对了 GetRecord、GetGroupFileUrl、GetGroupMsgHistory。未连接真实 QQ，不代表用户部署版本具备同样行为。实施前记录 NapCat 版本／commit 和能力测试结果，不能依赖浮动 main。

### A.1 事件合同

| 对象 | 标准／扩展 | 关键字段与适配约束 |
| --- | --- | --- |
| image segment | OneBot v11 标准 | 标准 file/url；NapCat 还可能带 file_size、summary、sub_type。url 可能退化成本地路径，甚至获取失败时段缺失；不能按字段名信任其为 HTTP URL |
| record segment | OneBot v11 标准 | 标准 file/url/magic；NapCat 常见 file/file_size/path、可选 url。线上段名为 record，不是内部枚举 voice；原始 QQ 语音可能是 SILK |
| file segment | NapCat 扩展，非 v11 标准 | data.file 为名称，file_id 为句柄，file_size、url 可选；不能要求永远附 URL |
| group_upload notice | OneBot v11 标准 | post_type=notice、notice_type=group_upload、group_id/user_id、file:{id,name,size,busid}；没有标准 message_id 或 @。通知 file.id 与 segment file_id 分开保留，不能假定相等 |
| reply segment | OneBot v11 标准 | data.id 仅定位引用，不含原始媒体内容 |

group_upload 必须新增专门的 notice 分支，不能伪装成普通 message 或绕过用户／群 ACL。通知的内部记录键使用 account/group/user、opaque file.id、事件时间等组成，不强造 message_id；重复通知和 file segment 的关联需真实样本确定，不能只按同名文件去重。未开观察模式时不建立被动候选；开启时遵循第 3 节最小元数据政策。

### A.2 动作合同

| 动作 | 属性 | 请求及限制 |
| --- | --- | --- |
| get_msg | v11 标准 | message_id；NapCat 可返回 group_id 等扩展字段，但依赖已知消息映射。跨群核验失败、撤回或映射缺失即失败，不作为任意历史永久查询 |
| get_image | v11 标准 | file；NapCat 可支持 file_id。标准结果 file 为实现端本地路径，NapCat 还可能返回 url、file_name、file_size、base64；不得直接读任意路径 |
| get_record | v11 标准 | file、out_format；NapCat 还支持 file_id。当前源码输出格式名单 mp3/amr/wma/m4a/spx/ogg/wav/flac，转换成功把 file/url 都写成本地输出路径并附 base64，依赖实际转码组件 |
| get_file | NapCat 扩展 | file 或 file_id；当前非空 file 优先。返回路径／url／名称／大小等，file_size schema 为 string，字段可能为空；禁止按文件名跨群搜索兜底 |

### A.3 传输容量与已实现的限制

当前插件 `transport.py` 的 WebSocket `max_msg_size=1024*1024`，而 NapCat 当前 GetRecord 直接在动作响应携带整段 base64。即使媒体源文件未超过拟议 10 MiB 音频上限，也可能先撞到 1 MiB 帧上限；音频转 WAV 还会扩大体积。不能直接接该动作并声称支持上述配额，更不能无界调大 WebSocket 上限。

优先评估 NapCat 文件指南介绍的 Stream API（官方说明 v4.8.115+，仍属扩展）或固定大小分块的受控媒体服务；在确定当前部署支持、鉴权、传输上限与跨容器行为前保持该路径关闭。若选共享媒体出口，确认所用动作不会先返回超大 base64；否则需服务端封装／合适接口，不能靠客户端“忽略 base64 字段”避免帧解析和内存开销。限制必须覆盖解码后的 PCM、base64、JSON 帧和并发总内存，动作请求有独立容量与取消处理。

本次保留1 MiB帧上限，并在 transport 层禁止 `get_record/get_image/get_file`；可执行获取仅走累计限额的已审核 HTTPS 或专用共享出口。没有实现或调用 Stream API。未有安全位置的 QQ 语音句柄明确 fail closed，不声称已解决真实部署的转码出口；详见实现文档。

文件直链有效期不是 SLA。官方指南提及图片约两小时且文件存在下载次数约束；本设计不缓存长期 URL，不承诺固定有效时长。过期最多在已授权同一引用内刷新一次，不扩大查询范围。

### A.4 待真实版本确认

部署 NapCat 与上游 main 的差异；file segment 与 group_upload 是否双报和先后顺序；notice ID 与消息句柄的对应；get_msg 的同群证据；群文件 packetBackend 能力；get_record 解码可用性及超帧风险；Stream API 的实际端点与鉴权；路径到共享出口的安全映射；历史排序及服务器限制。以上仍未实测，不因协议文档存在就列为已实现。
