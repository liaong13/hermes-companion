# 主动聊天：独立插件与迁移

从 `hermes-napcat 0.3.0` 起，主动参与由独立的 [hermes-social](../../hermes-social/README.md) 运行插件提供；NapCat 只提供可信事件、唯一群白名单、精确来源许可和受限收发。`0.2.0` 内嵌控制器是历史布局，不能继续只更新连接器版本号就宣称独立社交组件已经就绪。

本功能仍需要 strict、`runtime.mode: social_agent`／合同 5、兼容 worker，以及[候选安静交付](../../../integration/hermes-host/napcat-ambient-quiet.md)和[公开风格钩子](../../../integration/hermes-host/napcat-social-participation.md)。插件通过原生 `register_platform_handler` 与显式参与端口接线，不另开 OneBot 连接，不需要为这次拆分新增宿主接口。没有／关闭社交插件时，原有点名和主人私聊仍正常。

## 两种机会，两个授权路径

- 自然接话：真实白名单群未点名消息可成为候选，仍核验真实成员、sender、消息 ID、撤回和精确来源，走正式 gateway／工具回合。可以回答开放问题和连续追问，也可以选择 `NO_REPLY`，不是每条必答。
- 空闲开口：由独立社交插件考虑是否开启话题，只能使用明确 `targets` 中的精确目标。模型只有文本选择权，没有工具，不加载私人 SOUL、USER、MEMORY 或跨聊天历史；不能借用旧用户 source permit。

日常接话共用 NapCat 的 `allowed_groups`。`targets` 只限定空闲发送，不是第二套接话名单；扩充群白名单不会顺带增加空闲发送能力。`participation_groups` 仅保留显式测试／迁移覆盖，正式配置应删除，省略时直接取通道白名单。

## 当前配置命名空间

策略位于 `plugins.entries.hermes-social.settings.channels.napcat`，总开关仍须显式开启。以下号码仅为示例；只替换实际获准目标，不复制维护者现场。

```sh
hermes config get platforms.napcat.extra.allowed_groups
hermes config set plugins.entries.hermes-social.settings.channels.napcat '{"enabled":true,"targets":["dm:100000002","group:100000003"],"timezone":"Asia/Shanghai","quiet_hours":[23,9],"idle_after_seconds":1800,"min_idle_interval_seconds":7200,"daily_limit":3,"ambient_cooldown_seconds":20,"ambient_debounce_seconds":3}'
hermes plugins enable hermes-social
hermes config get plugins.entries.hermes-social.settings.channels.napcat
```

- `targets` 只接受精确主人私聊或通道已允许的群，不接受通配符、其他人的私聊或含糊纯数字。可以为空，只接话、不自动开新话题。
- 默认空闲至少 30 分钟才考虑主动开口，两次至少间隔 2 小时，每目标每天至多 3 次。无人回应不追发，未知回执不重放，模型可以不说。
- 默认 23:00 至次日 09:00 不自动开新话题，不阻断正常交流；两个小时值相同表示无该静默时段。
- 未点名消息默认合并等待 3 秒，冷场候选默认间隔 20 秒。真实社交发言后的短期连续窗口不重复套冷场冷却，但仍合并且不抢占正在处理的回合。
- 在社交参与和群图片云识别同时获准时，未点名纯图异步经已有下载、解析与视觉链路识别，并将不可信派生写入本群原消息的短期上下文；纯图本身不提交可选聊天回合、不自动回复。未授权或识别失败时只标记“有图，内容未识别”，不可借旧话题猜图。其他纯附件仍只观察类型；明确点名及经核验的机器人引用保持原有媒体路径。
- 未点名但同条带真实文字与授权附件，或明确问“刚发的图”等短期候选时，由通道在接纳时冻结来源和原始问题，再经参与端口复用媒体队列、当前网关配置的 Codex GPT 视觉与正式 gateway；不要求重新 @，也不把近期对话 JSON 当作识图问题。
- 在自然接话分流前保留经现有准入核验的短期元数据与引用来源，仍按群、作者和消息 ID 隔离；只观察不会下载。原候选撤回、过期或失效时拒绝，不重新挑另一张图。新消息撤销旧的可选回复，但不取消仍有效的纯图识别；可选接话最多等识图 5 秒，超时仍视为未知内容。暂停、撤回、断线及卸载撤销在途感知与可选媒体，普通点名路径不受牵连。

## 从内嵌 0.2.0 布局迁移

1. 备份当前配置、安装文件和旧状态。保留已有本地修改；先离线验证 `hermes-napcat`、`hermes-social`、worker 与宿主补丁组合。
2. 将原 `platforms.napcat.extra.proactive` 的完整策略通过配置 CLI 写入新命名空间，删除临时 `participation_groups`。**不修改 `allowed_groups` 或扩大 `targets`。**
3. 显式启用仅针对 counters-only 旧状态的一次性迁移：

   ```sh
   hermes config set plugins.entries.hermes-social.settings.migrations.napcat_state_v1 true
   hermes config unset platforms.napcat.extra.proactive
   hermes plugins enable hermes-social
   ```

4. 新状态位于当前 profile 的 `plugin-data/hermes-social/napcat/social-state.json`，旧文件仍保留。迁移在新插件取得真实通道端口、创建控制器之前发生：只在目标不存在时采用旧 `napcat/social-state.json` 的最新暂停、消费和计数；不覆盖已有新状态，不导入正文、昵称或长期记忆。
5. 不在旧服务运行时提前复制一次状态就当作完成，因为旧服务可能在复制后又消费一次空闲机会。迁移拒绝另一个活动网关 PID；正常重载后在新网关内采用停机后的最新文件。状态采用与文件安装是不同阶段。
6. 从独立管理终端执行 `hermes gateway restart`，核对新 PID、版本和连接，再在获准范围发送新消息验收。工具处于网关进程树内时，不通过分离进程或定时器绕过自身重启保护。

旧 `extra.proactive` 不再由连接器解释；只保留旧字段不会启用新社交插件。回退需要成套恢复备份的连接器文件、旧配置和插件启用状态；旧进程／新进程不能同时连接同一 OneBot。回退时不要盲目覆盖较新的暂停、消费或聊天数据。

## 风格、控制与权限

公开名字来自通道提供的已配置名称，表达自然、温柔、允许小俏皮，也保留严肃、犹豫和不同意见；不虚构亲历，不预设熟识。昵称、正文及近期资料属于不可信 user 输入，不进入固定 system 前缀，不授予权限。

群友可暂停本群自动参与，只有已核验主人可以恢复；暂停不阻断明确点名或主人私聊。保留旧命令，独立插件也提供 `/social` 别名：

```text
/napcat-social status
/napcat-social pause
/napcat-social resume
```

关闭 `channels.napcat.enabled` 或禁用社交插件并重载，保留原有明确寻址聊天。卸载社交插件撤销它的可选来源和空闲句柄，不撤销普通点名许可。群默认参与不授予主人权限，不公开私聊、私人文件、密钥或跨群资料；加好友及普通群友私聊仍不在本次范围。

## 状态、记忆与发送

近期缓冲按精确场所分开，只在内存保存有界近期文字，断线清空，不补拉历史，不是长期记忆或训练。空闲机会继续最多读取 16 条／1 小时；未点名候选可在内存中最多 64 条里按真实 @、发言者、已核验机器人引用及话题关联筛出近 10 分钟的最多 12 条。相同昵称不合并，模型只收到临时发言者别名，不收到 QQ 号；对另一位成员明确说话或对象不明时可静默，独立的开放问题仍可参与。当前消息不在近期 JSON 重复；标记为 `non_conversational` 的通知、进度、自动重置提醒和独立 runtime footer 不作为聊天，不刷新活动窗口或来源代数。

社交状态目录／文件为 `0700`／`0600`，只存暂停、日期、计数和检查／发送时间，不保存正文、昵称、密钥或群友关系。状态故障只暂停可选参与，不能阻断正常点名与私聊。

`hermes-scoped-memory` 继续负责按身份／来源的记忆归属。社交层提供只读作用域上下文接口，当前运行默认只有真实近期缓冲；worker 的 `prepare_proactive` 是准备校验，不是长期记忆检索。未经完整接线和生产验收，不宣称群友长期记忆已启用。

新消息、暂停、撤回、断线和卸载使在途可选许可失效。真实候选在准入、实际工具执行与发送时复验；空闲使用绑定目标、活动代数、连接代数、期限及本控制器的单次句柄，先持久化消费再发送，按准确消息 ID、目标、作者、类型与正文回读，未知结果不补发。

## 分层验收

在匹配的 Hermes 运行环境中分别运行两个插件测试、NapCat 部署测试和宿主增量测试。完整 native gateway／真实模型、但不连接 QQ 的验证见[真实模型验证](../../../integration/hermes-host/napcat-social-participation.md#完整网关与真实模型验证)。

脚本应同时注册两个真实插件，走 worker、持久化 FIFO、source codec 与 AIAgent，只将 OneBot 替换为禁止真实连接的捕获端；不能把单次 facade 回答冒充正式链路。检查缺插件、停用、重复接线、跨人／跨群／跨 profile、暂停和迟到操作，同时验证正常点名仍通。

源码测试、安装组合、活动网关加载、OneBot 回读和 QQ 客户端可见性分别报告。旧场景成功不证明拆分后新版本、其他通道、任意媒体或长期记忆都已验收。
