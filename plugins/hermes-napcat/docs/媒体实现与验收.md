# 入站媒体实现与验收

2026-10-27，任务起点 `历史修订`。这是仓库源码能力说明，尚未部署到已安装插件。真实 QQ 文本通道的历史使用事实不变；新增媒体、真实模型效果和固定 NapCat 版本仍待授权验收。

## 已落地的链路

`OneBot → self_id／用户／群／真实@ → strict Route → bridge.admit → 媒体引用／获取 → 无网络解析进程 → 辅助识别 → bridge v2 → 原对话模型 → 原目标回复`。

媒体只支持显式允许的群；私人 DM 仍走原文本路径。默认 `media.enabled=false`，不会下载、解析、索引或调用媒体模型。启用要求 strict、有界群触发（默认真实@，或显式name_or_mention）、媒体群与类型清单；群清单只能收窄现有 ACL。缺 bridge、旧 bridge、域准入失败均在获取前拒绝，不回落私人 agent。新factory／主人native生命周期、名称触发和provider模式见 [测试部署接线](测试部署接线.md)，本阶段语音不启用。

| 模块 | 职责 |
| --- | --- |
| `adapter.py` | ACL／触发、notice、独立任务、有界排队、撤回取消、原目标回复能力 |
| `media.py` | 闭合配置、来源合同、单层引用、同发送者候选、部分失败与总文本额度 |
| `media_io.py` | HTTPS／DNS／SSRF、共享出口 dirfd 安全读取、bubblewrap 解析进程 |
| `media_worker.py` | 图片规范化、文档提取、真实音频解码、可选本地 faster-whisper |
| `media_provider.py` | 固定 OpenRouter 视觉模型、独立 audio fallback、调用预算预占与安全错误码 |
| `process_owner.py` | parser／worker共享进程所有权；重复取消期间保留启动与回收任务，确认进程和管道关闭后再传播取消 |
| `runtime_bridge.py`、`hermes-scoped-memory/isolated_worker.py` | `media_contract=2` 握手及有界、不持久化的媒体问答分支 |

出站仍只有纯文本。图片固定调用 `qwen/qwen3-vl-30b-a3b-instruct`，由规范化 PNG 构造 `image_url` data URL；最后回答使用社交 worker 原有 `chat.json.model`，没有替换对话模型。图像 API 结构依据 [OpenRouter 官方图像输入](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding)。音频使用带 `format=wav` 的 base64 `input_audio`，依据 [官方音频输入](https://openrouter.ai/docs/guides/overview/multimodal/audio)。这些协议依据和 loopback 载荷测试不证明真实 provider 在线或识别质量。

## 触发、索引和撤回

- 同条真实 @：按 segment 原顺序处理，最多四个附件；保留文字、附件序号和各自错误。
- 真实 @ 加 reply：仅查询一层 `get_msg`。返回的 `message_id`、原作者权限和 sender 一致性必须通过；显式 `message_type`／`group_id` 必须与当前群一致。若查询省略群来源字段，只接受此前已从认证 OneBot 连接收到的同群、同账号、同域及策略版本、同消息 ID 和作者事件作为来源证据。该索引仅存来源元数据，120 秒有效、最多 4096 项，撤回或断开即清除；无证据、跨群或私聊仍拒绝。不会递归引用、forward 或取群历史。明确引用可选中另一个已获 ACL 授权的作者，结果保留原作者；纯文字作为不可信引用文字送入公共问答，失败时提示“引用未处理”，不称为媒体。
- 引用机器人自己消息时，无论正文是否已用名称或真实 @ 触发，都先用 `get_msg` 核对同群、消息 ID、机器人 `user_id` 与一致的 `sender.user_id`，并检查本地撤回标记；通过后将引用作为回复锚点；合同 4 将有界可见文字放入本轮不可信引用上下文，不解析引用里的附件。同条用户附件仍走媒体路径。合同 5 的 gateway 连续文字引用尚有内容传递缺口，不宣称完全支持。机器人引用缺少群字段、来源不明或字段冲突时不推断身份，也不依据引用内文字、QQ 昵称或群名片放行；有正文触发的请求继续由原媒体来源校验拒绝。机器人自己的同群撤回 notice 记录墓碑，阻止随后再次接受该锚点。
- 非 @：默认不留附件候选。只有 `observe_metadata=true` 才在域准入后保存最小附件元数据；不下载、不识别、不建立对话。附件候选索引按账号、域、策略版本、群、发送者隔离，120 秒主动清理，每来源十项、全局 128 项。启用引用时另存前述不含内容的事件来源索引，与附件候选无关。唯一候选才关联；重启不恢复。
- 当前真实 @ 可用 `/media image`、`/media record`、`/media file` 或“分析我刚发的文件”等明确表达选择同群、本人、短时唯一候选。可选 `/media file <opaque-id>` 精确选取已观察到的句柄。请求接纳／入队时冻结当时已准入、可见的候选、scope、原来源和到期时间；“无候选／歧义／观察关闭”也冻结为当时结果。执行时只复核冻结项的TTL、索引仍存在、撤回、当前ACL／媒体策略及完整Route，不重新选取。失效就拒绝或取消，之后出现的新文件不能替代旧候选；请求时歧义也不因后来撤回变成唯一。没有候选或存在歧义时要求引用，不枚举群文件目录。
- `group_upload` 没有标准 @ 或 message_id，仅在观察模式记录 `file.id/name/busid`；不会自动聊天。notice 的内部来源以 `notice:` 标识，不制造 QQ 消息。仅在同 scope 的非空 opaque ID 确实相等时与 file segment 去重，不按文件名猜测映射；不同 ID 保持独立候选。
- 同群 `group_recall` 清除相关索引并取消引用它的未完成任务；十分钟、最多4096项的撤回标记阻止重放恢复候选或再次读取已撤回的引用。只有上传 notice、尚无消息映射时无法据 message_id 推导文件关系，仍由短期 TTL 和任务取消限制。真实 @ `/media cancel <触发消息ID>` 只能取消当前群、当前发送者的任务；取消指令独立准入，不排在目标任务之后。断开、超时和任务取消同样撤销回复能力、终止子进程。已经发送给云或 QQ 的内容无法由本地取消收回。

## 获取与帧上限

WebSocket 仍为 **1 MiB**。`get_record/get_image/get_file` 在 transport 层拒绝发送，防止上游整段 base64 在客户端检查字段之前就撞帧上限；未提高上限，也未发明 Stream API endpoint。此行为依据 [NapCat GetRecord 源码](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/file/GetRecord.ts)，部署前须固定版本复核。

可执行的通路有两种：

1. 已认证且通过同群来源校验的附件 URL 按显式下载策略处理：默认 `allowlist` 仅允许精确 `download_hosts`，空清单拒绝；`public_https` 取消目标域名过滤，不要求配置 hosts。两者均只允许 HTTPS／443，拒绝凭据、fragment、控制符、反斜杠、歧义数字／域名、私网、回环、链路本地、元数据、保留及 IPv6 映射／过渡地址。DNS 返回的所有地址必须为可接受公网地址，实际 connector 直接使用这些结果，禁 DNS 缓存和二次查询；混合公网／私网整体拒绝。TLS 证书链及主机名校验保持开启，禁重定向、代理环境、cookie和自动解压，累计流量计限、独立连接／读取／总时限。不会把 OneBot token 或模型 key 带到媒体主机。普通聊天文本 URL 不成为附件，不新增抓取入口或联网工具。
2. 部署者提供专用共享出口，配置真实宿主 root 和 NapCat 容器 prefix。只允许 prefix 内相对路径；从 `/` 起逐级以 dirfd 和 `O_NOFOLLOW` 打开，包括 root 的父目录。要求 root 为当前用户 0700；拒绝软链接、FIFO、非普通文件、多硬链接、穿越、超限和读取中变化。不能把 NapCat 任意路径直接 open，也不能挂载整个 NapCat profile。出口由部署者预先完成受控复制，插件不调用会返回巨量 base64 的转码动作来“生成出口”。

文件句柄没有直接位置时只使用同群 `get_group_file_url(group_id,file_id)`。语音仅有 opaque handle、容器路径未映射或 SILK 解码器不可用时返回安全失败；真实跨容器出口尚未验证。这是部署条件，不声称所有 QQ 原生语音现在都能取到。

## 下载策略与配置迁移

`media.download_policy` 是闭合字符串枚举：仅 `allowlist`／`public_https`，省略时为 `allowlist`；未知值、null、布尔、数字、列表或对象均拒绝配置。`download_hosts` 若存在仍必须为精确小写 ASCII 名称列表；公网模式不使用该清单作过滤，迁移时删除该字段，避免留下错误的限制预期。空列表不会改变旧模式的拒绝行为。

父任务在审核后的原配置中仅进行以下下载字段迁移，不用模板覆盖整个配置：

```yaml
platforms:
  napcat:
    extra:
      media:
        download_policy: public_https
        # 删除此 media 下原有的 download_hosts 字段
```

群清单、`group_admission`、owner／DM身份、媒体类型、云许可和预算不随此字段迁移扩展。按既有域迁移流程提升 `isolation.policy_revision`、建立匹配且未复用的专用 `runtime.social_home` 和状态版本；若当前仍为 revision3，下一版应为4，由父任务用原生配置 writer 写入、读回并独立部署／启动验证。本阶段不读写线上配置、不安装或重启。

**取消域名过滤不等于没有网络／解析风险。** 公网附件服务器仍可提供恶意内容、消耗资源或记录访问；SSRF限制和无网络解析沙箱只是边界的一部分，不会执行附件／宏，也不证明解析器不存在漏洞。新增回归在合成 DNS 下把已验证公网连接参数映射至本地 TLS 服务：真实传输、证书链／主机名、重定向、大小和超时均运行；不证明真实公网CDN、签名URL或QQ客户端已验收。任务提供的前序第三人图片通过事实不等于本次新下载策略通过。

## 解析能力与实际限制

所有解析在 bubblewrap 中运行：`--unshare-all --clearenv`，不分享网络、不挂载私人 home、配置或密钥；仅系统运行库、解析脚本、任务 tmpfs，以及代码显式注入的只读 Whisper runtime／模型。无 bubblewrap 或启动失败直接拒绝，没有宿主无沙箱 fallback。任务文件目录 0700、文件 umask 077；进程退出后 tmpfs 原件及派生文件消失。没有跨 scope 的内容摘要缓存或磁盘媒体缓存，因此不另设一小时媒体缓存。

| 类型 | 当前能力与边界 |
| --- | --- |
| PNG／JPEG／GIF／WEBP | magic、声明 MIME 一致性、ffprobe 像素检查；ffmpeg 单帧重新编码为 PNG，不复制 EXIF。至多 32MP，任一边≤16000，预览最长边4096。超长图明确提示缩放，尚无分块 OCR；动画仅处理首帧 |
| UTF-8 TXT／Markdown／CSV | 本地纯文本、行号；CSV 使用实际解析器并保留物理行号，不执行公式或链接 |
| PDF | `pdfinfo/pdftotext` 文本层、页码。最多100页，提取前20页并提示；扫描件明确无文本层、未做 OCR。拒绝加密、动作／脚本／附件／外链等标记，以及可隐藏对象的 ObjStm；这是保守支持子集，部分普通现代 PDF 也会被拒绝 |
| DOCX／XLSX | ZIP 条目／展开总量／压缩比限制，XML 禁 DTD／实体；拒绝宏、ActiveX、嵌入、外链关系等。DOCX 段落序号，XLSX sheet 文件序号及单元格坐标；公式仅展示，不计算。PPTX、旧 Office、加密包、普通 ZIP unsupported |
| record 音频 | ffprobe 探测真实编码，ffmpeg 转16kHz单声道16-bit PCM WAV；最长120秒；静音、解码或长度失败直接返回，不送 fallback。无法保证 ffmpeg 支持部署 NapCat 的 SILK 变体 |

解析输入每附件10 MiB；OOXML最多512项、单项8 MiB、总展开16 MiB、压缩比≤100；解析进程内存2 GiB、CPU60秒、文件16 MiB、普通解析墙钟30秒。输出每附件约12 KiB，最终任务正文最多24 KiB，附截断提示。四附件串行保序。全局两个媒体任务、每群一个，最多18个任务（含活动任务），新任务超额丢弃并计数；总任务120秒。与草案的20 MiB文件、长图分块和一小时缓存等提案不同，以本表和源码为准。

## Whisper 与 audio fallback

默认首先尝试本地 faster-whisper；缺包、缺本地模型均明确返回 `whisper_unavailable`，不联网安装或下载。部署者在批准安装后可通过宿主代码注入：

```python
# paths must be reviewed dedicated runtime/weights, never a whole private home.
sandbox = MediaSandbox(
    python='/srv/napcat-asr/venv/bin/python',
    runtime_mounts=('/srv/napcat-asr',),
    models='/srv/napcat-asr/weights',
)
service = MediaService(settings.media, sandbox=sandbox)
adapter = NapCatAdapter(config, isolation_bridge=bridge, media_service=service)
```

解释器所依赖的实际 Python prefix 也需在审核的 mounts 内；`-I`、无网络、`local_files_only=True`、CPU int8、有限线程仍保留。模型目录不与模型输入混用，解析进程不继承 key。此代码是现有可调用接口，当前未安装该部署环境。本机仅验证真实解码、缺依赖失败和提供者合同，没有运行真正 Whisper 推理。

fallback 还要求同时配置 `audio_fallback_model=google/gemini-2.5-flash` 与 `cloud: [audio]`。只在 Whisper 不可用，或实际 segment 的 `avg_logprob < -1`／`no_speech_prob > .6`／空转写时触发；这些是显式启发式，不是校准准确率。低质量原转写保留，与 fallback 文本分别标出，不合并成“更准确”的新稿；fallback 失败仍保留原文。解码、静音和超限不触发云端补救。Qwen3-VL 禁止作为 audio 模型。模型清单能力不等于真实 endpoint／语言效果已验收。

## 云权限与预算

辅助模型 key 仅由网络提供者主读取 `OPENROUTER_API_KEY`，标准变量不存在才兼容 `NAPCAT_MEDIA_OPENROUTER_API_KEY`，存在但空／非法不会回退；不接受配置明文、URL key 或日志输出，OneBot key 不复用。`cloud` 仅允许 `image`／`audio` 两项，默认空。`allow_derived_text` 还需显式允许派生内容进入原对话模型；它为 false 时获取前拒绝。辅助提供者请求禁止 endpoint fallback，要求 `data_collection=deny` 与 `zdr=true`；这只是路由要求，真实 provider 合规与可用性须部署者核验，不能从测试断言成立。

开启 cloud 默认采用 `budget_mode=local`，必须给出 owner-only 的独立预算目录、每日调用数、美元预估上限和每次预占美元数。SQLite 在请求前事务预占，每日以UTC日期计数，账目保留七天；磁盘操作在线程执行，不阻塞消息读循环。429、余额错误、断网、超时和计费未知均不自动重试、不释放预占。仅将返回的有效 cost 当作 provider 报告费用，缺失则记 unknown；实际费用高于预占时纳入后续限制。硬调用次数与未知账单预占跨重建保留。部署者显式选择 `budget_mode=provider` 时不建本地费用账本，依赖供应商key额度；不混用local预算字段，不改变权限／并发／载荷／时限，也不证明供应商额度已生效。

审核后的字段示例（保持关闭，群号和目录需部署者替换；不含 key）：

```yaml
media:
  enabled: false
  groups: ["20001"]
  types: [image, file, record]
  references: true
  observe_metadata: false
  download_policy: allowlist  # 默认精确域名；public_https 可省略 download_hosts
  download_hosts: []
  allow_derived_text: false
  cloud: []
  # 需要辅助云模型时才显式加入 image/audio，并设以下预算：
  # budget_directory: /srv/napcat-media/budget
  # daily_calls: 20
  # daily_usd: 1.0
  # reserve_usd: 0.05
  # audio_fallback_model: google/gemini-2.5-flash
  # 专用共享出口另行审核，两个键必须一起设置：
  # export_root: /srv/napcat-media/export
  # export_prefix: /media-export
```

预占金额是部署估计，**不是供应商强制美元封顶**；需同时设置供应商账户额度。最终原对话模型沿用既有独立计费设置，未计入辅助调用预算。本轮无付费调用，因此没有真实账单、OCR／ASR准确率或p50/p95。

## 版本合同与原生准入

宿主 `MessageEvent` 已有 `media_urls/media_types/media_text_inlined` 和 `allow_gateway_control`；native ingress 的 metadata 是闭合合同，不允许插件自造字段。测试用真实宿主验证混合本地媒体字段、数组及禁控制字段可准入；实际媒体实现只走 strict v2，**不把远程 URL、原件路径或原始 OneBot payload 交给普通私人 agent**，也未启用 legacy 原生媒体路径。

`probe` 必须返回 `media_contract: 2`。`dispatch_media` 消费一次性 Admission，校验 source 不变，再发送 `{schema_version:2, operation:'chat', route, text, attachments}`。worker 校验闭合字段、类型、数量和总预算，附件按原序保留 `kind/origin/author/segment`、文本、错误、方法和警告。原文与附件分开 JSON 编码；不拼为 `/forget` 或 `/memory-*` 命令。

v2 分支在记忆服务和命令解释器之前执行，无工具，不读写记忆、不持久化该媒体轮的历史；只把本轮必要问题与非可信附件交给原模型。纯文本worker的命令／记忆分支、主人私人记忆和人格策略不变；媒体模式的适配器调度按下节改为有界后台分发。图片／文件／转写不能自动成为公共事实。媒体最终对话拥有独立 worker semaphore，不占用普通文本 worker 通道。回复能力在整个任务内有效，返回、取消或失败即撤销，始终绑定原触发群与消息。

### 安全返修后的时序合同

独立审阅发现先前两个中风险问题：普通strict文本等待完整模型调用，堵住OneBot消费者处理后续撤回／取消；媒体选择请求在取得群锁后才查当前索引，会绑定到触发之后才出现的文件。R1／R2已获二次独立复核确认修复，保留现有回归；后续重复取消资源问题R3单列如下，不推翻已成立结论，也不把旧DONE当成全部验收。

媒体启用时，`OneBotClient._consume` 仍是同一认证连接的FIFO事件入口；适配器在ACL、真实@和事件去重之后，把普通strict文本放入独立有界分发，立即归还消费者。普通文本最多18项、活动上限2、同chat串行FIFO、总寿命120秒；原worker文本逻辑及私人策略不变。取消控制另有8项容量和20秒寿命，不占文本／媒体群锁；它仍先做相同来源校验、strict域准入，只能取消同群本人任务，回复能力绑定自己的触发消息。撤回仍经相同ACL在消费者内执行清理，不进入模型。

worker的本地 `probe` 有独立单并发通道，不与普通文本或媒体模型请求共用semaphore，避免取消又在准入阶段被慢文本挡住。解析／worker创建子进程时保留受shield保护的启动句柄，取消到来后也回收已创建进程；结束时排空并关闭pipe，而非只wait PID。断开会取消并等待文本、控制和媒体任务，撤销回复能力。各队列满时丢新项并计数，OneBot仍为原64项队列和1MiB帧，不提供可靠持久投递；不同分发通道之间不保证回复总序。

冻结候选只读取同scope最小元数据，不下载、不调用云；真正获取和解析仍在域准入后。冻结来源从入队起就登记到任务撤回依赖，TTL同时限制任务剩余寿命；取消、过期、移除或策略改变后不可重选。同条附件的句柄与单层引用ID同样冻结，执行时仍重新检查当前来源、ACL／策略和撤回状态。

### R3：重复取消期间的进程所有权

之前仅shield第一次等待启动，异常处理中裸await同一launch，清理本身也可被再次取消。真实消费者先recall、随后disconnect时，第二次取消使任务结束并释放槽位，但已启动parser／worker仍活着。该问题是资源泄漏／可用性风险；复现未观察到越权或媒体误回复。

现在parser和worker共用 `ProcessOwner`：调用方、launch、业务I/O、唯一finalizer均有明确引用。调用方等待受shield保护的同一finalizer，第二次及后续cancel只记录待传播取消，不取消launch／finalizer；取得句柄后先终止进程／受控进程组，再取消并join业务I/O、回收进程、关闭管道。回收完成后原取消继续传播，不能把任务变成成功。整个等待仍在原任务／worker槽位内，不将清理留给无人等待的后台任务。

启动只执行本地标准库进程创建，不承载业务或网络等待；一旦开始，不能通过取消等待而丢弃可能已启动的句柄。取得句柄后的正常回收时限5秒，超时使用真实subprocess transport关闭FD并在2秒内核对退出／EOF；没有无期限communicate。该后备路径使用封装在一个模块内的CPython transport接口，已在当前managed解释器用真实管道验证，升级运行环境须复跑。

成功断开前核对returncode已确定、stdin关闭、stdout EOF。若仍无法确认，抛出固定 `ProcessCleanupError`；解析器／worker停止再次启动进程，适配器拒绝后续入站，并让disconnect报错，不伪装断开成功。正常重复取消不提前释放槽位；测试在交付／清理闸门未释放时断言原任务与群锁／worker槽位仍被持有。

R3先补4项真实回归，修复前全部失败；修复后6项覆盖parser／worker的启动交付、清理阶段再次取消，以及不释放清理闸门时的有界后备关闭。所有场景注入recall后disconnect，并再取消一次，最终均为3次取消、进程退出、stdin关闭、stdout EOF、无待执行finalizer、无迟到回复。父任务后续已独立验收R3和103＋5基线；新host factory下另补真实worker重复取消回归。
