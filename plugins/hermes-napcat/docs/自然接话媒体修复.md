# 自然接话媒体分流与自然引用修复（0.3.1～0.3.2）

## 问题与修复范围

`0.3.0` 的未点名入口在排入自然接话后提前返回：图片只变成 `[attachment:image]`，没有进入媒体处理，还漏过短期索引与引用来源登记。正式会话仍保留既有历史，因此模型可能把没有图像内容的占位符误接到旧话题。这不是已证实的视觉供应商解析错误。

本修复不清空会话、不更换模型或登录、不扩大群／成员／媒体许可、不放开通用视觉或主机工具，也不把图片/OCR 当作人类操作确认。

- 纯图／纯附件：在已启用媒体的群内按原准入观察元数据，不自动下载、识别或开启可选模型回合。
- 未点名真实文字＋附件：无需固定唤醒词，接入既有 `resolve → enrich → dispatch_media`。明确的“刚发的图”等选择也能使用原短期候选。
- 真实 @、正文名称、经核验的机器人回复锚点保留原路径；未点名回复其他成员不因此变成新的寻址方式。
- 媒体绑定留在通道：接纳时冻结精确 event/source、不可变 `MediaRequest` 与原始问题；社交插件不取得原始事件、签名 URL、OneBot client 或私人资料。
- 可选请求最多 64 项，期限不超过 120 秒；原候选过期、撤回、清除或失效时拒绝，不重新挑选后来出现的图片。
- 新同群消息、暂停、撤回、断线和卸载撤销可选媒体；下载、解析、识别、派发与失败回复各边界复验。普通点名媒体不随可选参与暂停而取消。

图片理解仍使用既有 `qwen/qwen3-vl-30b-a3b-instruct`；主模型沿用当前 profile 的配置。模型看见图片内容不等于获准执行其中的命令。

### 真实视觉与正式 native 捕获链路

新增 [验证器](../../../integration/hermes-host/verify_napcat_ambient_media_live.py)，必须显式 `--live`；它会消耗真实模型额度，但永不连接真实 OneBot。

源码组合已实际通过两个场景：

1. 未点名纯图片：真实 worker 核验后登记索引与来源，未启动 parser、视觉、native、主模型或发送。
2. 未点名文字＋图片：真实 `MediaSandbox` 图片归一化 → 一次既有 Qwen-VL HTTP 请求 → 真实 strict worker prepare → 持久化 FIFO/source codec → 正式 `GatewayRunner/AIAgent` → 一次既有主模型 HTTP 请求 → 本地捕获发送与回读。

图像为本地生成的无敏感 256×128 PNG：左红色方块、右蓝色圆形。源码实测最终回答为“左边是红色正方形，右边是蓝色圆形。”两次模型 HTTP 均为 200，原生最终 user 和实际 HTTP body 均含真实视觉派生，不是只有占位符；实际 wire 保留 20 个工具定义，工具可见不等于任意执行获准。parser／worker 进程已退出并 join，隐私 canary 未进入模型或输出，本轮生成物凭据扫描通过。

该测试只把 QQ 图片下载替换为精确固定 URL 的本地真实 PNG，QQ 发送替换为捕获端。它不证明真实 QQ 下载、活动网关已加载新代码或用户客户端已经看见回复；用户原图未读取。

## 0.3.2：先发图后自然询问

后续实际反馈暴露了引用识别覆盖不足：独立发送“看一下上一张表情包是什么内容”没有被旧 `selection()` 认作图片选择，只把近期图像占位符交给模型。此前“刚发的图”和同条文字＋图片通过，不能证明这一自然说法通过。

本版只修媒体引用类型识别，加入指代、常见图像名词与明确看图请求的组合；不靠重新点名，也不把无效 `/media` handle 修补成另一种请求。识别后的来源绑定仍使用原有群／作者／TTL／唯一候选校验：其他成员、其他群、多个候选、撤回和过期不因此获得读取能力；不新增模型、工具权限或历史搜索。

新增 `test_media_selection.py` 8 项方法、自然引用完整路由 6 项回归；媒体回归现为 33 项。插件完整 311 项（3 项既有跳过）、社交 75 项、部署 5 项、宿主 13 项均通过。新增验收判据 helper 5 项通过。聚合 logging／SQLite 资源警告仍保留。

验证器增加 `--scenario followup`：第一条只有合成图，第二条只有上述原话，不再把图片重复放进提问来冒充引用测试。须证明图片 `origin` 是前一条、request route 是当前提问，原始问题原样进入真实 Qwen-VL，派生进入 worker／native 最后 user 及实际 wire，工具和隐私边界不变。源码组合已真实通过；测试图仍为本地红方块／蓝圆形，未读取真实用户图片或连接 QQ。

首次 followup 运行的真实链路已正确描述两种图形，但旧验收器沿用“请说左右”的同条图片规则，错误要求仅问内容的回答也显式说左右，造成测试误判。原失败报告保留；补充正确颜色－形状配对、错误配对及错误位置拒绝的 helper 回归后，按原话重新进行真实请求并通过，未改写模型输出。一般内容问题不强制额外方位措辞；主动陈述的位置仍须正确，同条明确问左右的用例保留原严格规则。

安装与活动进程重载仍须分层核验。重启会清空短期索引，重载后的客户端测试应发送新图再按原话询问，不拿重启前的短期候选当作仍然可用；明确引用原消息另走既有同群来源核验。

## 安装与重载边界

安装副本验证与活动进程重载分开执行。安装前备份并确认已有本地差异，逐文件核对，不整目录覆盖。保留当前配置、社交状态、登录和群／媒体白名单。

本轮源码真实链路已通过；当前安装与重载状态以本次最终执行记录为准，不能从本页推断已经生效。安装后应使用明确的 `--plugin-root "$HERMES_HOME/plugins/hermes-napcat"`、`--social-plugin-root "$HERMES_HOME/plugins/hermes-social"` 重新运行捕获验收。

若执行工具位于网关进程树中，不得绕过重启保护；由主人在独立终端执行 `hermes gateway restart`，再核对新 PID、加载和连接，并发送新的 QQ 消息验收。至少测试不点名的文字＋图、纯图后明确询问“刚发的图”、撤回和正常点名；截图/OCR 不代替敏感操作授权。

## 后续授权：纯图识别供自然接话参考（尚未提升版本）

用户进一步明确授权：白名单群的纯图片也可通过已配置的视觉模型识别，供本群短期自然接话参考。此行为只在社交参与启用、当前群和图片云处理获准时发生；纯图本身不自动开启正式聊天回合，也不发送 QQ 回复。图片来源与群成员一致性、原消息撤回、断线、暂停、卸载和策略变化仍逐次复核；识别失败只留下“图片内容未识别”标记，不把占位符或旧话题当图像内容。连续文字消息不会取消仍有效的纯图识别，后续可选回合最多等 5 秒；超时仍以未识别状态进行判断，不猜图。

源码 NapCat 323 项（3 项既有跳过）、social 77 项、部署 5 项通过；聚合日志仍有既有的 logging/ResourceWarning 噪声。源码及安装组合均使用无敏感合成图完成真实视觉 HTTP → 短期上下文替换和正式文字+图回合捕获验收：纯图一次视觉请求、零正式主模型回合/零发送；同条文字+图另一次视觉请求、一次正式主模型回合及本地捕获发送。未连接真实 OneBot，用户原图未被重读，活动网关尚需独立终端重启与新消息客户端验收。上一节关于“纯图只索引”的说明属于此前版本的历史行为，不能用于此项变更后的运行状态。

## 后续调整：多人话题路由与当前 GPT 图像理解

按最新授权，图片辅助不再固定 OpenRouter Qwen-VL：群媒体解析和来源绑定不变，识图通过宿主的 Codex OAuth 凭据池与网关当前 `model.default`（本次只读核对为 `gpt-6-luna`），不会跟随 CLI 会话级 `/model` 临时切换，也不回落旧视觉模型。音频云 fallback 仍由独立配置负责；图片模型不授予图中文字任何操作权限。若默认模型不再是可用的 Codex GPT，图片识别应明确失败，不静默改用其他服务。

多人未点名候选不再机械发送最近 16 条。仅在原白名单内、从本群最多 64 条内存观察中筛选近 10 分钟最多 12 条与当前问题相关的消息；先处理真实 @、已核验同群机器人引用及可信发言者关系。含糊短句和明确对别人说的话可在模型调用前静默，独立的公开问题仍可开始新话题；混合 @ 含机器人继续走正常点名。昵称只用于展示，模型看到临时发言者别名而不是 QQ 号；工具和发送权限仍按原来源证明核验。

本次源码完整单测：NapCat 327 项（3 项跳过）、social 89 项、部署 5 项、验收辅助 5 项通过。真实 Codex `gpt-6-luna` 的合成图捕获验收在源码组合的 direct 和 followup 场景均通过，纯图一次视觉请求但没有自动发送，后续正式回合实际使用视觉派生；社交 `all` 场景中有价值的问题经过 worker／持久队列／AIAgent 与本地捕获，明确他人话语及表情在模型前静默。原 256×128 合成图的图形形状曾被 GPT 误读为长方形，失败报告保留；将验收图扩大到 512×512、保留原有颜色和几何配对判据后实际重跑通过。这说明链路可用，不证明所有低分辨率几何识别都准确，更不代替真实 QQ 下载、发送与客户端验收。安装副本和活动进程状态须以最终部署记录为准。

历史阶段曾同步十一项源码文件，并连同三个配套文件核对安装副本；备份标识与现场进程时间不公开。随后针对路由标签误读复跑源码及合成模型夹具。安装同步不等于活动网关已经加载，客户端验收当时仍待单独重载后执行；本段不保留现场对话内容。

## 重启后简短补答静默回归

历史诊断中，曾观察到一次已被机器人追问的交流，其后同一发言者的简短补答未形成正式回合。本文不保留原话、地名、参与者身份或现场时间。日志覆盖不足，不能仅凭缺少回合日志证明消息已到达路由；另用重新编写的合成输入验证了当时措辞筛选存在漏接路径，也不能据此将所有失败都归因于模型静默或发送失败。

修复只对有来源证明的短答开放：成功发送的机器人问题保留其真实出站 `reply_to` 消息 ID；当前发言者须是被回复的原消息作者、仍在同群短窗口、之后没有其他成员插话，才将不含问句的简短实质答案与那条问题一起送给正式候选回合。无锚点、不同发言者、过期、他人插话以及“好的”等简单附和仍静默；昵称、伪引用和模型推断不能创造回复关系。源码 social 92 项、NapCat 328 项（3 项跳过）、部署 5 项及验收辅助 5 项通过；真实 GPT／本地 OneBot 捕获的单项短答和完整社交 all 均通过，捕获报告保存于 `$TMPDIR`。这证明修复后的源码链路会接续，不等于旧活动网关已重载或真实 QQ 客户端已经验收；安装与运行需另核。

历史安装记录覆盖了七个变更文件，安装前有私有备份并核对过副本；备份标识、具体时间和现场对话不公开。原安装组合的八个场景报告仅属于当时版本，已经替换的测试数据不能沿用旧的行为验收结论。安装同步与网关重载仍是两个阶段，不能重放旧消息冒充新的客户端验收。
