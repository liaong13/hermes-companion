# 群权限与昵称：部署验收

自有文档遵循仓库 MIT 许可证。

## 当前状态

匹配的插件、兄弟 prepare-only worker 及配置已经落位并读回核对；**仍需用户从独立终端重启网关，才能确认新版本加载**。本页不是“QQ端到端已全部通过”的声明。

- 显式设置 `group_admission: all_members`；原群清单和私聊用户清单保持不变。
- `runtime.contract`、worker的 `host_contract` 与 prepare schema均为4；当前下载策略调整后revision4，通道和新专用社交home保持一致。
- 图片／文件和正文名称或真实@触发继续沿用，语音关闭，没有安装Whisper。
- 群内包括主人只走无工具、无私人记忆的单次公共facade；主人私聊保持native处理。
- 当前群名片优先于QQ昵称；不读好友备注或私人姓名，不用显示名认证。
- 群友长期记忆管理未上线；没有扩大跨群／普通私聊或管理能力。

## 用户配合步骤

1. 在独立终端执行 `hermes gateway restart`；不要从网关自身的工具进程绕过重启保护。
2. 核对新进程、NapCat新连接及合同配置后，在原测试群按名字或真实@触发。
3. 引用同群其他成员发送的非敏感图片，请示例呼唤名读出图中文字和数字；这是此前作者白名单问题的直接复测。
4. 用普通成员账号测试名字触发与当前群昵称；主人在群中也只能使用当前群昵称。
5. 测试非敏感小型TXT／CSV文件，再测试撤回／取消和主人私聊原功能。
6. 跨群／普通私聊／伪造身份仍须拒绝；不为测试扩大群清单或主人权限。

每一步独立记录客户端实际结果；图像来源通过不等于下载、解析、视觉效果或最终送达都通过。失败时按所在层排查，不退回放宽所有来源的策略。
