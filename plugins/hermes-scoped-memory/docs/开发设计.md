# 分域记忆开发设计（待用户评估）

本方案基于 `历史修订`，于 2026-10-26 至 2026-10-27 核对；只形成设计，不代表已实现或获准上线。自有代码与文档 MIT，不复制 LivingMemory 的 AGPL 源码。完成度以 [开发状态](开发状态.md) 为准；[早期问题评估](记忆系统问题与改进建议.md) 仅保留追溯。

2026-10-27 用户要求开始编码，0.2 本仓库实现及离线验收已落地，见 [实现与验收](实现与验收.md)。下文保留评估时的目标与差异，不把尚缺的宿主 bridge、LLM 正式接线、公共确权或真实云端验收算作完成；部署授权与代码开发授权分别处理。

## 结论与职责

保留私人 default 的内置 MEMORY／USER 与既有主人 Mem0 共享配置。新增一个社交信任域，在其中按可信用户和精确来源隔离本地记忆，不为每位成员创建 profile。社交域下一版采用 `local-only`，不持有 Mem0 凭据，不创建主人委托。云端 embedding 优先评估 OpenRouter，向量和权威数据均存本地；不具备合规 provider 时仅用关键词。

NapCat 负责协议认证、身份和 ACL；宿主负责在 agent 构建前强制准入、路由与工具／上下文权限；记忆提供者负责已授权范围内的归档、提取、召回与删除。不能以记忆库过滤代替宿主权限。具体通道设计见 [NapCat 接入与隔离设计](../../hermes-napcat/docs/接入与隔离设计.md)。

同进程 profile 仅隔离配置和数据路径，不是 OS 沙箱。面向不完全信任成员，建议使用独立系统账号／容器的社交执行域，禁止挂载私人 home、云记忆凭据和私人历史；可信入口向该执行域传递最小消息和不可伪造身份。单个 OneBot 连接由一个入口持有，消息分发需验证，不在两实例重复启用连接。这些宿主工作属于后续独立授权范围。

## 现有实现与下一版差异

| 当前证据 | 下一版落点 | 兼容要求 |
| --- | --- | --- |
| `../__init__.py:_read_settings` 全局要求 builtin 两项显式 false | 按部署模式验证：社交 local-only 必须无私人注入 | 不为通过首版预检关闭私人 default；旧 composite 模式保持原门槛 |

| `Store.search` 词重合＋一跳标签 | 范围内关键词＋向量＋RRF | 关键词始终可独立工作；不承诺新依赖已经安装 |
| `Store.mutate` 只改状态 | 归档、纠正、忘记三个独立动作 | 旧 `delete` 明示软删除，不能静默变成硬擦除 |
| `max_injection_tokens` 为字节 | 新 `max_injection_bytes` | 旧字段作为同单位别名并告警；两者冲突拒绝加载 |

## 可信范围与强制准入

范围结构草图（不是现有宿主 API）：

```text
ScopeContext = {
  domain_id, platform, principal_id, origin_kind,
  origin_id, thread_id, session_id, message_id,
  policy_revision, deletion_epoch
}
```

`principal_id` 来自已认证 NapCat 协议 ID；`origin_id` 为精确 dm/group/thread 来源，群和私聊不同命名空间。`domain_id` 由宿主部署绑定，不能由工具参数指定。私聊仅本人＋该私聊；群中个人记忆仅本人＋该群／线程；群公共事件仅显式授权的本群。默认不跨群、不从私聊带入群，主人在群内也走社交规则。名称只用于显示，不能把同名成员合并。

宿主 `gateway/profile_routing.py:ProfileRoute.matches` 是 AND 匹配，specificity 中 user_id 权重高于 chat_id，且无 chat_type。禁止单独的 owner user_id 路由到私人 default；私人规则必须同时精确匹配 platform、`dm:<OWNER>`、user_id，入口再校验 dm 类型。未知路由、歧义、目标不可用必须拒绝，不能依赖 matcher 返回 None 后的默认回落。策略与 agent 缓存键包含 domain／policy revision；旧私人上下文不能复用到社交 agent。

准入顺序：协议身份与 ACL → 精确路由 → 域／工具／文件／历史能力审核 → 干净会话与 agent → 记忆提供者。准入失败必须在任何私人提示词、工具、历史加载前阻止调用。普通观察钩子若异常后宿主继续聊天，不算强制准入实现。需审查 terminal、文件、history/session_search、技能及项目上下文、cron、delegate、管理工具和出站通道；委派不能丢失原域，定时任务不得回退到主人。

## 数据与接口草图

在现有 `sources/memories/terms/associations` 上增量迁移，不直接重写旧表；新增字段先允许兼容回填，最终约束由迁移版本控制。

| 实体 | 主要字段／约束 |
| --- | --- |
| `sources` | 原有 owner/origin/session/message_id/hash；增加 domain、source revision、授权状态；幂等键须含平台／域／来源／消息／角色，不能只按文本哈希合并两条相同发言 |
| `facts` 或扩展 `memories` | subject、asserted_by、participants、visibility、evidence/source、event_time、revision、state、expires_at、supersedes；身份字段程序填入 |
| `extraction_windows` | scope、起止来源、revision、summarized_cursor；只在成功提交事实后推进游标 |
| `outbox` | job_id、scope 快照、source/window revision、policy revision、deletion_epoch、type、idempotency_key、state、attempts、lease_until、next_run_at、error_code |
| `vector_generations` | 模型 ID／provider／可获得的模型修订、dimension、dtype、归一化、预处理与前缀版本、距离函数、状态、active generation |
| `vectors` | memory_id＋fact revision＋generation 唯一；内容哈希、域、范围／可见性及向量；SQLite 内容为权威，向量为派生索引 |
| `scope_versions`／删除墓碑 | 授权修订、删除 epoch、缓存修订；防止异步结果和旧备份重新生成被删除内容 |

拟议服务接口：`resolve_scope(trusted_event)`、`append_turn(scope, turn)`、`enqueue_extract(scope, window)`、`apply_candidates(scope, revision, candidates)`、`search(scope, query, policy)`、`forget(scope, targets)`。不向模型暴露 owner/domain/visibility 写权限；工具层即使收到这些字段也应拒绝，而非采纳。返回值区分 denied/not_found（对外统一）、durably_accepted、pending、degraded、failed，不把入内存队列当成功持久化。

持久引用包括 source_id、message_id、证据片段的字节或字符坐标及其单位、内容哈希、source revision；模型不能伪造来源。校验片段必须存在于允许窗口，ID 必须来自本次输入白名单；引用回溯重新检查当前权限和删除状态。UI 只给范围内原文分页，不把整个归档注入主提示词。

## 自动提取与 LLM 接线阻挡

本机普通 `hermes_cli/plugins.py:PluginContext.llm` 返回宿主 `agent/plugin_llm.py:PluginLlm`；`complete_structured` 和 `acomplete_structured` 接受 instructions、text input blocks、json_schema、timeout、max_tokens、task，结果含 parsed。宿主文档见 [官方插件 LLM 接口](https://hermes-agent.nousresearch.com/docs/developer-guide/plugin-llm-access)。schema 校验依赖可选包，因此插件还必须执行本地字段、长度、枚举、证据与权限校验，不只相信 parsed。

**与原先假设不同：记忆提供者的上下文取决于加载路径，不能直接套普通插件示例。** 同进程路径的 `plugins/memory/__init__.py:_ProviderCollector.__getattr__` 只转发 `register_*`，直接取 `ctx.llm` 抛 AttributeError。用户目录插件若采用 host 路径，register 收到 `hermes_cli/plugin_host_child.py:_CapturingContext`，能取得 `RemoteFacade`；但方法探测／调用通过 `plugin_host.py:_serve_facade` 回到父进程 collector，再访问其 `llm` 仍失败。因而 `hasattr(ctx, 'llm')` 或拿到代理不能证明可用。此结论来自源码链路，未启动宿主子进程或调用模型。

`ctx.register_auxiliary_task(...)` 可走注册转发，但 collector 会捕获转发异常并返回 None，不能把未抛异常当成注册成功；工作者启动前应验证任务注册结果及所属插件。现有 `../__init__.py:register` 仅 `ctx.register_memory_provider(ScopedMemoryProvider())`，没有 LLM 引用注入。方案不调用私有 `ctx._plugin_context()` 绕过契约。

下一版首选向宿主确认／补齐正式 collector LLM facade 暴露与进程代理契约，再在注册时将受限 facade 注入 provider 或域内服务。若使用普通插件发现阶段注入，必须有正式稳定的服务注册接口与跨发现顺序握手，验证同源去重、profile 绑定、host 子进程、重载与 shutdown；当前未核实此机制存在，不能先写一个全局 singleton 缓存跨域 ctx。只有通过这些验证，才能持有进程生命周期内的 facade 引用；引用不序列化到 SQLite，重启从宿主重新取得，持久任务只保存 task ID 和作用域。

辅助任务 `scoped_memory_extract` 通过 `register_auxiliary_task` 注册，复用宿主允许的模型配置和权限，不直接读取认证文件，不让抽取器覆盖 profile／agent／provider。初期不指定额外便宜模型，先测宿主任务质量与独立费用。抽取请求只含同一允许范围内的窗口和少量相关旧事实，无工具权限；模型只返回候选 facts，不执行写库或授权。

处理顺序：本轮文本＋outbox 同事务提交 → 同 scope 合并窗口（建议最多 8 轮、输入上限待 tokenizer 验证）→ 提取候选 → 校验证据、身份、修订及敏感性 → 事实与游标同事务提交 → 派生向量任务。明确“记住／纠正”可优先；闲聊按轮次或空闲触发，避免每句收费。回滚、编辑、删除或窗口修订变化时废弃旧结果，不推进游标。

候选内容包括事实类型、内容、主体建议、陈述者、时间、来源片段、关联、置信与替代建议；程序最终绑定陈述者和权限。玩笑、引用、转述、推测、助手推断、密码等敏感信息不直接作为已确认长期事实；转述保留 asserted_by，不冒充当事人。低置信或冲突为 pending，不能靠模型置信分数自动确权。

## 群公共事件

个人事实与群公共事件分表或显式 visibility，查询分别执行授权谓词后融合。只有本群公共项目、群规、明确约定等经规则／确认才能入公共库，不能把成员私聊画像搬入群。公共记录的参与人是资料而非授权名单；跨线程共享须显式策略，初期保留精确线程范围。

“A 说 B 明天来”保存为 A 的陈述，B 的确认作为另条证据。发言者可撤回自己的陈述，不能替他人改写；冲突并列并请求澄清。共同事件修改需要群规则授权，管理员显示 role 不能自动获得权限。个人忘记请求撤除本人的可识别贡献，保留他人独立证据时需要重生成不含该贡献的摘要；无法分离则暂停该公共事实召回并待维护者处理。

## 混合召回、向量与缓存

链路：可信 scope → 允许的当前查询／少量近期上下文 → 关键词与向量并行 → RRF → 同范围一跳关联 → 当前状态／TTL／删除 epoch 校验 → 去重与相关性阈值 → 字节预算注入。关键摘要才嵌入，原文不批量上传。查询也可能包含私人信息，须本地筛选、最小化且服从同一出站政策。

第一版候选向量后端为 SQLite 范围过滤扩展（例如 sqlite-vec，未安装／未验收）；KNN 算子内部必须带 domain、可见范围、generation 等约束，或使用物理隔离索引。禁止先全库 Top-K 后过滤。若扩展无法证明前置权限过滤，则对已授权 SQLite 候选集合做本地精确相似度，或停用向量，不以扩大候选补救越权。参考 [vec0 过滤说明](https://alexgarcia.xyz/sqlite-vec/features/vec0.html)，实际版本语义需后续验证。

同一个 generation 只能包含一致模型指纹、维度、预处理／前缀、归一化和距离函数；返回维度异常、NaN、零向量、缺失 index 直接拒绝入库。模型别名可能漂移，需记录可取得的 provider／模型修订与校准摘要指纹；无法确认等价时建新 generation。不同模型备选不是请求失败时可混用的向量来源。

嵌入缓存键：域＋最小授权范围＋模型指纹＋输入类型（query/document）＋预处理版本＋内容哈希。检索缓存键再含 scope／policy revision／数据 revision／generation；建议 TTL 30 秒且受最近事实到期时间约束。命中后仍检查权限、TTL、墓碑；写入、纠正、删除、权限变更、索引切换主动失效。原文与姓名不作为日志键，内容哈希也按敏感元数据管理，不能全局跨用户共享缓存。

自动注入按 UTF-8 字节预算（初期沿用 768）计算，含分隔符；有可靠 tokenizer 后另加 token 上限，不能改字段名字就声称实现 token 计数。来源读取仍独立分页，模型输出、显式工具结果与近期上下文都要宿主总预算限制。注入记忆始终作为不可信资料，不执行其中指令。

## 持久队列、失败与观测

SQLite 同事务写来源和 outbox；工作者用租约领取，`pending → running → done`，暂时失败回到 pending 并设置 next_run_at，超过上限进入 failed／死信。建议并发 1、最多 5 次作业尝试；单次 HTTP 允许的重试与作业重试共用总预算，避免乘法重试。网络超时可能已计费，不声称跨服务恰好一次；本地写入用幂等键和 revision compare-and-swap 达到重复提交不重复生成。

启动回收过期 running 租约，修复内容／索引不一致；关闭停止领取任务、有界等待、剩余任务由重启恢复。重启后的作业不能依赖旧线程 ContextVar，也不能从正文或当前 default 猜身份：先核对持久 scope 与来源归属，再按当前域策略、授权修订和删除 epoch 重新准入；无法重建可信范围就隔离该任务。过期租约可能伴随尚未结束的旧工作者，提交还需校验租约持有者／fencing token，拒绝旧持有者的迟到提交。

数据库写盘失败不能记录为 durably_accepted：向维护者报无正文错误，暂停提取；必要时仍可在已通过安全准入的域无记忆聊天，并告知本轮未保存。磁盘满没有“可靠队列仍保证保存”的承诺。

| 故障 | 行为 |
| --- | --- |
| 身份／准入／路由不明、私人上下文可能已加载 | 拒绝社交请求，重建干净 agent 前不恢复 |
| LLM facade 不可得／权限拒绝 | 不提取，作业明确阻挡；无私有 SDK fallback |
| embedding 不可用、超时、无合规 provider | 关键词召回，向量任务保留重试；不放宽隐私策略 |
| 本地库不可用 | 安全准入已通过才允许显式无记忆聊天；停止写入并报错，不切主人 Mem0 |
| 权限或删除 revision 已变化 | 废弃异步结果／缓存；重新解析当前政策 |
| 索引异常 | 隔离损坏 generation、关键词可用，影子重建 |

指标仅记录范围匿名标识、任务数量／年龄／失败码、token 与费用、缓存命中、各路耗时、索引代次和删除进度；不记录消息正文、真实账号、密钥或模型原始响应。监控不含任何已测 P50/P95 断言。

## 删除与隐私边界

归档退出默认召回；纠正创建新版本并保留可审计旧证据；明确忘记才执行授权范围内的删除流程。先事务建立墓碑／提升删除 epoch，停止召回和相关任务，再删除来源正文、事实／词项／关联／向量／缓存／未完成作业，清理或重建受污染摘要。工作者提交前再次比对 epoch，防止删除后复活。删除任务也需幂等和重启恢复。

跨参与者共享来源不能无条件整条清空或继续暴露，按贡献切片删除／重建；旧数据无切片能力时暂停相关事实并明确部分完成。对外区分“已停止召回”“活动存储清除完成”“备份轮换待完成”。WAL checkpoint、secure_delete／VACUUM 及文件系统／SSD 残留需要独立评估和维护窗口，不承诺法证级擦除。

删除清单必须与可回滚的事实库／向量代次分开保留，按域维护单调递增序号、目标 ID 与删除范围，不保存被删正文。备份记录删除序号水位，恢复或切换旧索引前必须重放到当前水位；若删除清单也恢复成旧副本，或不能证明水位完整，则拒绝恢复后对外召回。仅在所有相关备份过期／清除后才允许按政策缩减删除清单，不能因主库已清空就一并删掉墓碑。文件系统级快照也可能回滚清单，恢复流程必须能从独立保留的清单确认水位；此处是待实现要求，不是现有保证。

删除还需撤销包含目标事实的预取、agent 缓存和派生会话摘要；正在返回的召回结果在注入前再次检查删除 epoch。宿主若无法重建干净上下文，就暂停该会话并明确未完成项。已发送的 QQ 回复、其他参与者副本和外部模型已处理的数据不能由本地 forget 撤回，不应承诺“删除后从未出现过”。

主人 Mem0 删除仍走其授权路径，本地删除不代表第三方备份已擦除；社交 local-only 不调用 Mem0。云 embedding 的 ZDR、缓存及 provider 保留条件见 [选型](OpenRouter嵌入模型选型.md)，找不到符合隐私条件的 provider 时不出站。提取模型的出站是另一条数据路径，需单独审核，不能因 embedding 已获评估同意就上传完整归档。

## 迁移、重建与回滚

1. 在新隔离测试 home 用合成数据演练；本轮不操作真实 home。识别 schema，校验旧 owner/origin，不推断身份、不从路径猜用户。
2. 使用 SQLite backup API 生成一致备份并校验恢复；WAL 活跃时不能只复制主数据库。迁移前空间不足或备份失败即停止。
3. 事务执行 schema 版本升级，记录迁移日志与计数；旧行先标 legacy scope，无法映射者隔离而非公开。旧软删除／过期记录不转成 active，不自动产生公共事实。
4. 新 outbox 仅对授权有效摘要建立，旧原文不自动云端重提取；需要回填时由操作者选择范围、预算、隐私政策。
5. 向量影子 generation 构建期间旧关键词继续服务；核对数量、维度、授权过滤、抽样检索和中文基准后原子切换 active generation。回滚仅切回已验证旧代次，不混查。
6. schema 回滚用备份恢复，不让旧版本打开未知新 schema；从独立保留的删除清单重放至当前水位，再允许对外检索；旧版本不能执行该守卫时不得回滚上线。新建社交会话／agent，不清空既有私人历史；撤回社交接线须独立授权，不能顺带改私人 default。

## 参考、差异与接口映射

2026-10-26 至 27 查看 [dafeiyu-astrbot README](https://github.com/whyever77/dafeiyu-astrbot) 和 [MIT LICENSE](https://github.com/whyever77/dafeiyu-astrbot/blob/main/LICENSE)：该项目是 AstrBot/NapCat 集成包装，README 将实际记忆指向 LivingMemory，描述按 session 划分及身份显示标记。目录页获取失败后，成功只读核对公开的 [包装插件 main.py](https://raw.githubusercontent.com/whyever77/dafeiyu-astrbot/main/plugin/astrbot_plugin_face_convert/main.py) 相关段落，未作全仓审计。

该包装在入站处理里用 `get_sender_id/get_group_id/get_sender_name` 构造身份标签写入 `message_str`，通过 `_fy_tagged` 避免重复标记；admin 列表决定显示“主人”，不是 Hermes 的权限依据。其表情冷却以 `event.unified_msg_origin` 分会话并过期，可借鉴避免全局缓存串扰；本方案的记忆缓存还必须加入域、用户、来源、权限和数据修订。该包装会读取 AstrBot 配置、处理媒体并记录部分标记；不移植这些认证和日志方式，也不据此声称其实现了 Hermes 所需的隔离。

[LivingMemory 架构](https://lxfight-s-astrbot-plugins.github.io/astrbot_plugin_livingmemory/architecture) 描述统一引擎、会话归档、事实、混合检索、修订守卫和缓存失效；[依赖仓库](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 标明 AGPL-3.0。只借鉴分层思路，不复制其源码或把包装项目 MIT 推及依赖。本方案重新设计 Hermes 的接口和权限策略。

| 参考概念 | Hermes 当前落点 | 本方案差异 |
| --- | --- | --- |
| 包装项目身份标记 | NapCat `display_identity`／`channel_context` | 显示与权限分离，身份从协议＋宿主来源取得 |
| session 作用域 | `ScopeContext`／Store owner＋origin | 会话重置不改变持久身份；同群还区分个人与显式公共事实 |
| 会话存储／统一记忆入口 | Store sources／provider 工具和生命周期 | 复用当前表，增加事务 outbox；不移植 AstrBot 钩子 |
| 自动总结与修订控制 | `sync_turn` 后台任务／拟议窗口 revision | 官方 LLM facade 仍有 collector 接线阻挡 |
| 混合检索与缓存 | Store.search 后续扩展 | KNN 内权限过滤先于召回，SQLite 作为权威存储 |
| 临时注入 | MemoryProvider.prefetch | 验证 Hermes 注入和压缩生命周期，不照搬 AstrBot 特定标记 API |

## 阶段任务与验收清单

这是完整目标清单；0.2 完成的子项与当前阻挡见 [实现与验收](实现与验收.md) 和测试报告。原有 32 项历史测试不计作后续目标的验收结果。

| 阶段 | 任务 | 通过条件 |
| --- | --- | --- |
| P0 安全接线 | local-only、精确路由、宿主准入、受限执行域、干净上下文 | 主人私聊仍可用；主人在群不读私人池；未知／畸形路由拒绝；文件／历史／delegate／cron 无越权 |
| P1 可靠数据 | schema、来源幂等、outbox、租约、修订、删除墓碑 | 进程中断／磁盘满／重复消息／并发纠正不串域、不重复事实、不静默假成功 |
| P2 提取 | facade 正式注入、辅助任务、schema／证据校验、窗口 | 普通发现与 provider-only、重载／子进程／多 profile 均绑定正确；无证据事实拒绝 |
| P3 检索 | OpenRouter 合成评测、KNN 过滤、RRF、缓存、影子切换 | 中文同义召回收益有记录；跨用户／跨群泄露为零；不相关查询抑制；模型不混代 |
| P4 公共事实与删除 | 确认／冲突／参与者贡献、完整删除恢复 | 未经授权不能公开／覆盖他人；删除后任务／缓存／恢复不复活 |
| P5 端到端 | 获授权后真实 QQ 多账号、重启、压缩／重置 | 人工客户端核对范围、失败降级和出站；证据脱敏；用户批准后才部署和扩大白名单 |

阶段表示开发依赖，不是逐阶段开放真实成员的授权。P2／P3 先使用合成数据；真实消息自动入库、云端处理及群公共记忆开放前，必须完成 P0 的准入、P1 的恢复守卫和 P4 对相应数据的删除／缓存撤回验收，不能等真实数据积累后再补“忘记”。

中文合成集计划至少覆盖同义改写、同名人物、否定／纠正、相对时间、群公共约定、引用转述、无关查询、提示注入与越权；分开发集／固定验收集，报告 Recall@K、MRR／nDCG、误召回、泄露数、耗时和 token 成本。具体阈值在基线测量后由用户确认，不能提前编造质量或 P50/P95。

仍需用户评估的产品决策：原文保留期与备份轮换、群公共事实确认方式、云提取可接受范围及月度费用上限。工程待验证项为 collector 正式 facade 契约、宿主拒绝入口、合规 provider 和向量后端过滤语义；这些不应靠降低隔离标准解决。
