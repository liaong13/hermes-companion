## 已落地的本仓库接口

| 层 | 实现与检查 | 边界 |
| --- | --- | --- |
| 配置 | `settings.py` 验证 `schema_version=2`、`mode=local-only`、独立域、修订与字节预算 | 只检查目标 home；不关闭私人 default 的内置记忆。local-only home 含 `mem0.json` 时拒绝 |
| 身份 | 冻结 `ScopeContext`；每请求从可信 ContextVar 解析，绑定当前删除 epoch | 正文、昵称和工具参数不授予身份；社交模式不开放 CLI 主人回退 |
| 数据 | 旧数据保留 `legacy` 域；SQLite backup 成功后事务迁移；归档与 outbox 同事务 | 迁移备份是内容库，不能用它覆盖独立删除清单 |
| 作业 | 持久范围、消息幂等、来源修订、租约、fencing、总尝试预算与死信；同一范围／会话空闲两秒后最多八轮合并 | 输入超限按完整来源切分，不截断原文；单个来源仍超限时该作业失败。旧权限／epoch／来源或租约提交拒绝 |
| 提取 | `HostExtractor` 只调用注入的宿主 `complete_structured`；二次验证 schema、原文片段和字符坐标 | 不读取凭据，不指定模型／profile；自动候选进入 `pending`，不直接确权 |
| 引用 | 证据含消息 ID、来源修订、哈希与字符坐标；原文修订保留历史版，读取重新校验权限／来源 | 历史证据不能冒充当前有效证据；原文显式分页，自动召回不注入原文 |
| 召回 | 前置 SQL 范围过滤后的本地精确 cosine、RRF、影子代次覆盖校验和原子切换 | 无需安装 sqlite-vec；查询和文档写入都必须匹配完整模型指纹；不混代 |
| 云 embedding | 默认关闭，固定审核 provider、ZDR、禁止 fallback、响应逐项校验、预算预留与熔断 | 只用 fake transport 验证；没有实际 endpoint 合规、中文质量或费用结论 |
| 忘记 | 独立删除清单先落盘，再清理本范围来源及依赖事实／词项／关联／证据／向量／作业 | `delete` 保持软状态；`forget` 不声称擦除旧提示词、外部副本或磁盘残留 |
| 迟到结果 | 注入前再验 scope／epoch；查询等待至多 800ms，同实例至多一个在途查询向量 | 无进程内检索缓存；超时结果不会直接返回给后来查询 |
| NapCat | strict 精确路由、`ProcessIsolationBridge` 和真实 bubblewrap worker；单连接入口，社交进程只拿最小消息和绑定回复 | 实际隔离、私有文件／环境不可见、禁止工具、确认和撤回已用本地服务验证；真实工厂和私人回调尚未部署 |

## 仅供隔离测试的配置

这是插件能够解析的配置示例，不是生产部署命令。目标 home 的 `config.yaml` 必须明确设置 `memory.memory_enabled=false` 和 `memory.user_profile_enabled=false`；该 home 不放主人 Mem0 配置。私人 default 不受此配置影响。

```json
{
  "schema_version": 2,
  "mode": "local-only",
  "domain_id": "social-example",
  "policy_revision": 1,
  "isolation_reviewed": true,
  "max_injection_bytes": 768,
  "source_retention_days": null,
  "extraction": {"enabled": false},
  "embedding": {"enabled": false},
  "public_group_memory": {"enabled": false},
  "jobs": {"concurrency": 1, "max_attempts": 5}
}
```

旧 `max_injection_tokens` 按相同 UTF-8 字节单位兼容并产生弃用告警；两个字段冲突拒绝。配置版本与 SQLite schema 版本分别管理。模式、域、主人映射或 policy revision 变化后旧 provider 拒绝操作，需要显式更新 scope 策略并重建 agent。

新 `sync_turn` 在成功提交后返回 `durably_accepted`，失败返回 `failed`，不会把内存排队当作保存成功。Hermes 当前上层是否向聊天用户展示失败仍由宿主负责，不能据 receipt 声称宿主已完成失败通知。旧 composite 模式保留原内存归档队列，避免静默改变主人委托时序。

`ScopedMemoryProvider(extractor=HostExtractor(...), retriever_factory=..., query_embedder=...)` 为实例级注入点。服务必须绑定同一 home／domain；retriever 由工厂接收本 provider 的 Store。`query_embedder(scope, query, timeout=0.8)` 返回 `{"vector": [...], "fingerprint": Fingerprint(...)}`，无指纹或调用失败即关键词降级。

`register` 注册辅助任务并使用正式 `ctx.bound_llm` 绑定合同复核实际任务归属；**不从 collector 私有字段获取 LLM、不建跨 profile singleton**。当前运行宿主尚未应用本仓库补丁，因此旧宿主安装仍没有完整自动提取接线；补丁在临时副本验证，插件初始化会比对 home／plugin／任务归属，host 模式通过 `ctx.bound_session.snapshot()` 逐请求读取可信身份，不依赖子进程环境。

模型工具新增 `pending`、`forget`、公共提案／查询／本人撤回，以及 `source` 的 `source_revision`。`forget` 必须指定当前范围的 memory/source ID；没有模型可调用的整域删除或公共确权参数。`Store.confirm(scope, id)` 是操作者数据层接口，不作为模型权限暴露。公共确权只由可信事件入口执行一次性 grant；独立 worker 的 `/forget-all` 直接解析本人原始命令，不执行模型输出命令。

## 恢复与仍然阻挡的验收

删除清单位于 `$HERMES_HOME/scoped-memory-deletions/ledger.sqlite3`，内容与向量位于 `scoped-memory/memory.sqlite3`。每次读写前重放未应用删除；清单 UUID 不符、序号缺口、低于内容水位或丢失均拒绝。恢复内容备份时必须独立保留当前清单。**同时回滚整个 home 或文件系统快照无法靠同一快照里的文件证明最新水位**；缺少独立可信水位时禁止恢复后上线，当前没有自动操作系统快照恢复认证。

embedding 费用账已迁到独立 `scoped-memory-billing`，并要求显式配置 profile 外 checkpoint；回滚主内容库不会退款，UUID／序号／哈希链不符或外部 checkpoint 丢失时拒绝。旧 `budget_recovery_verified` 布尔值不能单独放行。未知 usage／网络超时的预留不释放，费用不记零。transport 已以墙钟 deadline 返回、限制单个在途线程，迟到响应丢弃；不声称已取消上游计费或强制终止底层网络请求。

下列事项仍不能算完成，不能据离线测试开放真实成员：

- **P0 实际部署**：隔离 worker 和 bridge 已实现并真实 namespace 测试，仍需连接真实工厂、私人完整 turn 回调，审查实际 OS 配置及单一 OneBot 连接所有权。
- **P2 宿主应用与真实配置**：collector、host RPC 和正式身份快照已有可应用补丁及临时集成验证；真实宿主尚未应用，不能据此说生产安装可用。
- **P3 云端中文效果**：固定合成基准已有 Recall@K／MRR／nDCG 和本地耗时；没有实际 provider 中文质量、付费 token、网络延迟或真实成本结果。
- **P4 公共库启用与普通宿主缓存**：可信确认／冲突／贡献撤回及独立 worker 新上下文已实现。普通提供者还需注入绑定本 store 的公共服务；普通 Hermes 的历史缓存／摘要没有被全局改写，不能声称完整“忘记”。
- **P5 真实端到端**：真实多账号 QQ、重启、压缩／重置、出站和部署均未执行，需要文档要求的独立授权与宿主配合。
