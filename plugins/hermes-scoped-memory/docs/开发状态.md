## 2026-10-31 的 0.2.1 缺陷修复

普通 provider 注册新增显式 `embedding.local_http` 接线：只访问 literal loopback HTTP，后台为 active 事实回填向量，查询范围由 SQL 前置过滤，失败／繁忙降级关键词并提供 `status`。没有运行时的 `enabled=true` 明确报告阻挡。原有 cloud transport 仍需受信注入，没有自动配置 OpenRouter。独立 worker 未接入此向量运行时。

个人 pending 候选新增 `/scoped-memory pending|review|confirm|reject`，核对码绑定内容、证据、修订、期限、策略和删除 epoch。普通 SDK 命令使用实时身份并复核所选 provider；独立带记忆 worker 解析原始命令，模型输出不执行。当前宿主 NapCat 群通用 slash 门槛不放宽，合同 4／5 的无记忆路径不会自动得到该入口。

完整套件 **207 passed、2 skipped**；NapCat **329 项、OK（3 skipped）**，包含新增真实 bubblewrap 命令用例。命令、跳过项和限制见[测试报告](测试报告.md)，配置见[README](../README.md)。这些是源码与合成服务验证，没有部署或真实模型／QQ 验收。未来人物分层插件和社交连接仍在[方案阶段](../../../docs/社交能力与分层本地记忆.md)；下面 2026-10-27 的矩阵保留当时状态。

## 历史运行环境与证据级别

当时的只读配置检查与消息收发记录表明：主人使用自己配置的 Mem0 主体供跨 agent 共享；builtin memory/user 开启，NapCat 工具集为 `hermes-cli`，`group_sessions_per_user=true`，仅主人账号放行，实验 scoped-memory 未启用。个人主体标识已脱敏；这些历史条件不能当作其他部署的默认值，也不代表当前运行状态。

宿主静态核对：`gateway/profile_routing.py` 支持 platform/chat_id/user_id 等 AND 匹配，没有 chat_type；返回 None 不等于全网关拒绝。同进程 `_ProviderCollector` 直接访问 `ctx.llm` 不可用；host 子进程虽可取得远程代理，方法探测／调用仍回到缺少 llm 的父进程 collector。普通 `PluginContext.llm` 存在不能证明这两条 provider 接线已可用。注册转发失败还可能被捕获，需验证辅助任务实际注册结果。详见 [设计](开发设计.md)。
